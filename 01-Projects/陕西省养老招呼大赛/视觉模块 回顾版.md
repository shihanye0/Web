# 一、整体定位：这不是深度学习检测模型

而是一个：
> **传统计算机视觉 + 轻量监督学习 + 时序状态机**
架构。
核心思想：
利用场景固定、杯子颜色固定、任务流程固定的特点，用低算力方法实现可靠检测。

# 三、视觉模块包含哪些“模型”？

严格来说，它包含两个机器学习/算法模型：

---

# 模型1：HSV颜色分割模型（规则模型）

## 类型

传统计算机视觉规则模型。

不是学习模型。

---

## 输入

RGB/BGR图像：

```
640×480×3
```

转换：

```
BGR → HSV
```

---

## 输出

颜色mask：

例如：

药杯：

```
orange_mask
```

水杯：

```
blue_mask
```

---

## 作用

回答：

> 哪些像素可能属于杯子？

例如：

原图：

```
桌面

       🟧
```

输出：

```
000000

001110
011110

000000
```

白色区域：

可能是杯子。

---

## 参数来源

HSV阈值通过校准得到：

例如橙杯：

```
H:
5~18

S:
110~255

V:
99~255
```

蓝杯：

```
H:
88~112

S:
80~255

V:
73~255
```

---

# 模型2：1-NN最近邻分类器

## 类型

监督学习算法：

```
Instance-based Learning
实例学习
```

不是神经网络。

---

## 输入

18维特征：

例如：

```
[
visible,
rule_state,
area,
bbox_x,
bbox_y,
bbox_w,
bbox_h,
bottom_y,
...
]
```

---

## 输出

判断：

```
on_table

or

off_table
```

---

## 工作方式

训练阶段：

保存人工确认样本：

例如：

```
样本1:

18维特征
label=on_table


样本2:

18维特征
label=off_table
```

预测：

新帧：

```
18维特征
```

计算距离：

```
距离历史样本1
距离历史样本2
...
```

找到最近：

```
继承标签
```

# 四、完整视觉流程详细串联

---

# Step 1：图像采集

摄像头：

输出：

```
640×480 BGR
```

每一帧处理。

例如：

```
Frame t
Frame t+1
Frame t+2
```

---

# Step 2：BGR转换HSV

目的：

让颜色更稳定。

BGR：

容易受光照影响。

HSV：

分离：

```
H 颜色
S 饱和度
V 亮度
```

方便判断：

“是不是橙色/蓝色”。

---

# Step 3：HSV颜色mask

两个检测器：

---

## 药杯

寻找：

```
橙色区域
```

输出：

```
orange mask
```

---

## 水杯

寻找：

```
蓝色区域
```

输出：

```
blue mask
```

---

注意：

mask不是目标检测结果。

它只是：

> 颜色候选区域。

---

# Step 4：形态学处理

目的：

清理mask。

操作：

```
Opening

=
腐蚀
+
膨胀
```

使用：

```
5×5 ellipse kernel
```

去掉：

- 小噪声
    
- 反光碎片
    
- 孤立颜色点
    

得到：

更加干净的杯子区域。

---

# Step 5：ROI限制

两个区域：

---

## scene ROI

例如：

```
[40,0,620,470]
```

作用：

判断：

> 杯子是否还在视野中

---

## table ROI

例如：

```
[40,140,620,470]
```

作用：

判断：

> 杯子是否仍在桌面区域

---

# Step 6：Connected Components

连通域分析。

作用：

把：

```
所有白色像素
```

分成：

```
区域1
区域2
区域3
```

例如：

HSV后：

```
橙色区域:

A 杯子

B 反光

C 噪声
```

连通域：

得到：

```
Component A
Component B
Component C
```

---

# Step 7：候选过滤

每个区域检查：

## 面积

例如：

```
>=210 pixel
```

---

## 宽度

例如：

```
17~143 px
```

---

## 高度

例如：

```
24~220 px
```

---

## 位置

例如：

必须在：

```
table ROI
scene ROI
```

---

留下：

```
最大合格连通域
```

认为：

这是杯子。

---

# Step 8：提取bbox

得到：

```
x,y,w,h
```

例如：

```
bbox:

x=300
y=250
w=80
h=150
```

计算：

## bottom_y

公式：

```
bottom_y=y+h
```

例如：

```
250+150=400
```

表示：

杯子最低点。

---

# Step 9：规则层初判

利用：

```
bottom_y
+
table_anchor_y
```

例如：

桌面：

```
anchor_y=462
```

---

## 杯子在桌上

```
bottom_y >=462
```

例如：

```
470>=462
```

输出：

```
on_table
```

---

## 杯子被拿起

```
bottom_y<462
```

例如：

```
250<462
```

输出：

```
off_table_visible
```

---

## 看不到

scene ROI没有候选：

```
not_visible
```

---

## 矛盾

```
uncertain
```

---

# Step 10：生成18维特征

用于1-NN。

包含：

## 可见性

```
visible
```

## 规则判断

```
rule_state
```

## 面积

```
log(area)
```

## bbox位置

```
x
y
width
height
```

## bottom_y

```
杯底位置
```

## table和scene两套信息

形成：

```
18维向量
```

---

# Step 11：1-NN修正规则

输入：

```
18维特征
```

输出：

```
on_table/off_table
```

目的：

解决：

规则边界问题。

例如：

杯子刚离桌：

规则：

```
off_table
```

但是历史经验：

类似状态：

```
on_table
```

1-NN可以修正。

---

# Step 12：四态presence输出

视觉模块最终输出：

## 1

```
on_table
```

杯子在桌上。

---

## 2

```
off_table_visible
```

杯子离开桌面，但还能看到。

---

## 3

```
not_visible
```

杯子消失。

---

## 4

```
uncertain
```

证据不足。

---

# Step 13：状态机理解行为

视觉模块只回答：

> 当前杯子在哪里

状态机负责：

> 用户完成了什么动作

例如：

初始：

```
药杯:
on_table

水杯:
on_table
```

用户拿药：

```
药杯:
off_table_visible
```

用户喝水：

```
水杯:
off_table_visible
```

完成：

```
SUCCESS
```

# 五、最终总结表

|模块|技术|作用|
|---|---|---|
|颜色提取|HSV Threshold|找到橙/蓝像素|
|mask清理|Morphological Opening|去噪|
|目标分组|Connected Components|形成候选物体|
|目标筛选|面积/宽高规则|排除非杯子|
|位置判断|ROI+bbox|判断桌面/空间|
|几何特征|18维Feature Engineering|描述状态|
|分类|1-NN|修正规则判断|
|行为理解|Finite State Machine|完成任务判断|

---

# 一句话总结整个视觉模块

> 摄像头采集图像后，系统先通过 HSV 颜色模型提取橙色药杯和蓝色水杯区域，再利用形态学处理去噪，通过连通域分析获得候选目标，使用ROI、面积、宽高和bbox几何约束筛选真实杯子，然后提取18维几何特征输入每个杯子独立的1-NN分类器，得到on_table/off_table/not_visible/uncertain四态，最后交给状态机判断完整的人机交互任务流程。

这个方案属于**固定场景机器人任务中非常典型的“可解释视觉状态估计架构”**。对于桌面药杯任务，这类方法往往比直接上大型视觉模型更容易做到稳定和可验证。
