本笔记记录 2026-10-13 的安装和验证结果。候选项目对照采用本次调研于 2026-10-12 核对的本机基线，版本和路径随升级可能改变。项目热度属于选择线索，不作为重复安装的理由。

### 对抗式复核：修正宿主入口与写入安全

2026-10-21 的对抗式复核按“宿主实际读哪个文件”重新验收，发现并修复了四类问题：

1. **Claude Code MCP 入口错误。** `~/.claude/.mcp.json` 不是全局入口，`claude mcp list` 实际读取 `~/.claude.json`。已改为合并后者，只追加缺失的 `puppeteer`；原有远程 `aihot`、`rea` 等宿主条目保持不动。旧的 hub 生成文件移到 `~/.agents/.backup/claude-dot-mcp.json.20261021-150317`。复核结果 6 项均 `Connected`。
2. **Gemini CLI MCP 入口错误。** CLI 读 `~/.gemini/settings.json`，Antigravity 才读 `~/.gemini/config/mcp_config.json`。已改为合并 `settings.json`，保留 `hooks`、`theme`、`tools` 等键；`gemini mcp list` 列出 6 项。当前目录未受信任，宿主统一显示 `Disabled`，属于信任策略而不是配置失败。旧的 `~/.gemini/mcp_config.json` 已移到备份。
3. **Codex 医生假绿灯。** `hub-doctor` 原来只检查投影片段，真实 `~/.codex/config.toml` 缺 `puppeteer`。现在 Codex 直接追加缺失的 `[mcp_servers.*]` 表，保留原文件和已有凭据；医生解析真实 `config.toml`。`codex mcp list` 已列出 `puppeteer`。
4. **宿主合并会覆盖同名项。** 宿主 JSON 配置已从“覆盖同名项”改为 add-only：只补缺失条目，已有条目（如 Claude 的远程 `aihot`、OpenCode 的 `rea`）保留宿主版本。代价是从 `servers.yaml` 删除或修改已有服务不会自动同步到宿主，需要手动清理或更新。

第二轮复核（同日）继续按“代码实际行为”核对文档与脚本，补了五处：

- **规则入口默认覆盖与文档不符。** `sync_rules` 原来对 symlink/copy 规则默认 `overwrite`，而 README 写的是“冲突默认跳过”。现改为与其它资产相同的 `skip` 默认，`--force` 也对规则生效；只有内容完全相同的旧副本会自动转软链，用户自有的 `AGENTS.md` 不会被静默删除。
- **copy 模式与薄壳规则漏检。** `hub-doctor` 原来只哈希 `SKILL.md`，其它文件同名同大小但内容变化会漏报；现在哈希全部文件（忽略 `__pycache__`、`.pyc`），核对 commands 的内容与软链目标，并检查薄壳规则的托管块及主正文、全部规则片段引用。
- **`hub-update` 会被前置状态中断。** `hub-status` 改为 doctor 薄入口后会因 issue 退出 1，在原 `set -e` 下同步根本不执行。现在前置失败不阻断同步，同步和最终状态分别返回真实退出码，最终状态始终输出。
- **Codex TOML 渲染与失败语义。** 补了字符串转义（服务器名不是裸键时加引号）；宿主 TOML 不可解析时只写参考片段、不改宿主文件，并让 `sync-profile` 以非零退出码报告，而不是静默成功。`--dry-run` 现在会区分“保留/跳过/覆盖”，并核对托管块是否已一致。
- **`sync_plugins` 空转。** 原来对每个端输出“expand portable content”但实际没有展开；现在只在确有可移植文件时提示需手工并入 `skills/`/`commands/`，没有内容就不输出。

### 调研结论：共享基地不是同构配置

1. **AGENTS.md 适合做跨端指令入口**。它是开放 Markdown 格式，Codex、Cursor、VS Code、Aider 等端都读；目录树中最近的文件优先。各端仍可用自己的入口名（`CLAUDE.md`、`GEMINI.md`、`.cursor/rules/*.mdc`），但正文只维护一份。参考：<https://agents.md/>。
2. **Agent Skills 是开放格式，发现路径由宿主决定**。`SKILL.md` 的目录约定和 frontmatter 可以共享，但 Claude、Codex、OpenCode、Qoder、Trae 的扫描位置不同。能原生读 `~/.agents/skills` 的端就不复制，读不到的端才投影。参考：<https://agentskills.io/>、<https://opencode.ai/docs/skills/>。
3. **MCP 是协议标准，不是配置标准**。同一个 stdio 服务在 Codex 是 TOML、在 Claude/Qoder/CodeBuddy 是 `mcpServers` JSON、在 OpenCode 是 `mcp` 与 `type: local` 数组。正确做法是从 `servers.yaml` 渲染到各端原生格式，而不是复制同一份 JSON。参考：<https://opencode.ai/docs/mcp-servers/>、<https://docs.qoder.com/zh/cli/mcp-reference>。
4. **社区实践同样倾向“共享知识 + 端适配”**。强制同构会带来重复副本、过期配置和凭据扩散；各端保留模型、权限、插件和加载时机的差异，反而更容易把共享资产用起来。这也与最初“基地供各 Agent 借鉴参考”的意图一致。多宿主安装经验可参考：<http://www.chenxutan.com/d/7515.html>。
