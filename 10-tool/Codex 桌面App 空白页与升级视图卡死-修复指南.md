# Codex 桌面 App 空白页 / 看不到对话内容 — 修复指南

> 2026-10-24 排查并修复。配套工具:`~/codex-skin`(换肤工具,现在同时携带防卡死看门狗)。

## 现象

- 打开 App 或点击对话,主区域只剩壁纸/空白,什么都看不到
- 内嵌的 ChatGPT 界面卡在「升级套餐」(pricing)页,提示「无法加载历史记录 重试」
- 重启 App 也没用,每次启动都复现

## 根因(完整链条)

1. App 的 ChatGPT 会话鉴权链条断裂(升级/结账 webview 的鉴权握手失败,其 cookie 被清空后未重新注入)。
2. 之后所有 chatgpt.com 后端 API 返回 **403**(conversations / models 等),所以:
   - **云端对话**(如「高中英语学习建议」,存在 chatgpt.com 服务端)内容拉不下来 → 原生视图 0 条消息,只剩免责声明 = 「内容太长看不到详细内容」的真相
   - App 把「当前视图」锁死在不可见的升级/结账嵌入层(`div.fixed.inset-0.z-30.invisible` + `about:blank?toUrl=…#pricing` webview),同时用内联 `display:none` 藏起**所有**原生视图 → 整窗空白
3. 该状态在启动时被重建(启动时的套餐/鉴权检查仍 403),所以重启无效。
4. 与皮肤无关(摘掉皮肤实测依然空白);「返回 ChatGPT」按钮、ESC、点侧栏 ChatGPT 项均无法退出。

## 已部署的自动修复:防卡死看门狗

已集成进 `~/codex-skin/tools/inject.mjs` 的注入载荷(`codex-skin use <皮肤>` 即携带,与皮肤无关常驻):

- 检测:嵌入层不可见(invisible)+ 主区域没有任何可见内容,持续 ~24 秒
- 动作:隐藏卡死层;把内容最丰富的原生对话的显示链强制恢复;每 3 秒重申(React 重渲染会冲掉内联样式)
- 撤防:当 App 自己正常显示嵌入视图(例如重新登录成功后)自动撤销干预
- `codex-skin off / restore` 会一并清理看门狗的痕迹

效果:即使 ChatGPT 会话仍然坏着,App 开机 ~30 秒内也会自动回到可用的原生界面(本地 Codex 对话可正常打开、可正常干活)。

## 彻底修复:重新登录(恢复 ChatGPT 会话)

看门狗只是保底;要让云端对话(高中英语学习建议等)重新显示内容,需要重登:

1. 确认代理可用:浏览器能正常打开 chatgpt.com(注意:2026-10-24 实测 shell 走 127.0.0.1:7890 出口时 chatgpt.com 根路径 403,出口节点可能被区域封锁,必要时切换 FlClash 节点)。
2. App 左下角头像 → **退出登录** → 重新登录,完成弹出的浏览器授权(desktop-auth)。
3. 登录成功后:403 消失、历史记录恢复、嵌入视图正常,看门狗自动撤防。

### 重登前想先读「高中英语学习建议」的内容

用日常浏览器(已登录同一账号 chatgpt.com)打开 chatgpt.com → 侧栏「最近」→ 高中英语学习建议,即可阅读;这份对话只存在于服务端,本地没有任何缓存副本(已全盘排查过 sessions/thread_history/IndexedDB/webview 缓存)。

## 其他注意

- 「梳理移动取杯后续工作/继续推进」等定时任务线程会高频切换 App 当前对话,排查时会看到标题自己跳,属正常。
- 排查/驱动 App 用的零依赖 CDP 小工具:`node /tmp/cdp.mjs eval|click-text|shot`(需 App 以 `codex-skin use` 方式启动,端口 9222)。如丢失可从本文件思路重建。
