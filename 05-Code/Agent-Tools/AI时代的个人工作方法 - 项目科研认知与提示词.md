# AI 时代的个人工作方法

用途：个人长期参考，用于选择项目、推进科研、安排学习，以及给 AI 布置可验收的工作。原文观点在下一节概括；后续流程、案例和提示词是结合个人工作场景提出的实践建议，效果需要用实际任务检验。

## 一分钟速查

- 开始复杂工作，先说清楚希望发生什么变化、凭什么判断完成、有哪些现实约束。
- 把可检查的一段完整工作交给 AI，让它在范围内选择步骤；把精力放在选题、关键取舍与验收上。
- 重要问题尽量接触原始数据、源码、日志与原始文献，要求具体方法和可复核证据。
- 需要探索时提出有挑战的目标，并限定成本和停止条件；失败结果也应帮助决定下一步。
- 学习时保留自己的解释、预测与迁移练习，区分“看懂 AI 的答案”和“能够独立使用”。

日常短任务无需填写整张任务表；只有可能改变结果的信息才需要明确。

## 原文提供的四个方向

Felix Rieseberg 将 AI 使用的进取方向分为四类：

| 方向 | 文章的基本意思 |
| --- | --- |
| Speed | 更快完成已有工作 |
| Altitude | 从当前任务追问它服务的最终结果 |
| Depth | 使用专业方法，深入底层材料与问题 |
| Range | 借用更多领域的知识、工具和方法 |

原文还强调工具与数据接入、外部验证，并提醒跨学科协作容易退化为角色扮演。这是一篇实践经验文章，不足以证明某种提示词在所有模型和任务中都更有效。[原文](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/)

对个人更有用的应用是：重新评估过去因为缺人、缺时间或不熟悉另一领域而搁置的问题，从中选择能低成本试验、并能得到真实反馈的一项。

## 个人接下来值得怎样做

### 选择值得投入的目标

每次准备投入较多时间，可以先判断：这项工作改善谁的什么处境？完成后会改变哪个决定？最关键的不确定性是什么？

| 工作场景 | 可以直接追求的结果 | 应留下的证据 |
| --- | --- | --- |
| 陪伴机器人项目 | 修复一种真实发生、能够复现的交互失败 | 原始记录、复现条件、修改结果、未覆盖场景 |
| 项目汇报 | 让听众判断进展、剩余问题及下一步验证 | 结论对应的实验、运行记录与限制 |
| 科研探索 | 弄清一个可检验的问题是否值得继续 | 相关原始研究、基线、关键实验及替代解释 |
| 个人工具与配置 | 减少某类任务的返工或人工介入 | 同类任务表现、检查成本与维护成本 |
| 跨领域学习 | 能解释机制，并在新例子中做出正确判断 | 独立解释、预测、实际应用及错误记录 |

这些是目标示例，不代表项目当前已完成或已选定这些任务。G1 项目的竞赛工程目标与独立科研目标需要分别确定；工程演示不能自动写成研究结论。

### 扩大可以尝试的范围

对感兴趣、但不熟悉的方向，可以先要求 AI 帮助建立一个小规模验证：需要什么输入，现成工具能完成哪部分，怎样发现结果错了，预计要投入多少。通过一次实际尝试再决定是否深入。

适合先试的工作通常有清晰材料、较短反馈周期和可复核结果，例如日志分析、离线原型、实验脚本、论文方法复现、数据检查与可编辑文档。涉及现场物理状态或外部承诺的工作，还需要对应的观察与责任边界。

### 保留领域判断

值得长期积累的内容包括：业务问题的来由、数据怎样产生、系统在哪些条件下失效、实验怎样区分解释、什么代价能够接受。AI 的输出越多，越需要这些知识帮助筛选。

把反复纠正 AI 的问题记成具体反例：它依据了什么、漏了哪个条件、哪条证据纠正了它。只有在不同任务中反复发生、且值得长期防止的问题，才考虑沉淀为规则或 Skill。

## 用 AI 完成项目

### 一段完整工作的最小约定

复杂任务在现有任务记录中留下这些内容即可，不必另建一套管理系统：

| 内容 | 需要说明什么 |
| --- | --- |
| 目标 | 实际使用者或系统将发生什么变化 |
| 完成条件 | 哪个可观察结果足以接受交付 |
| 材料 | 当前版本、源码、相关日志、输入与已知事实 |
| 约束 | 必须保持的接口、资源、owner、数据和操作边界 |
| 关键未知 | 当前最可能改变路线的缺口 |
| 验证与停止 | 怎样判断对错，何时交付、换方法或报告阻断 |

允许 AI 在约定范围内完成查证、实施、检查和修复。出现未知时，先推进不依赖它的部分；只有会改变目标或关键取舍的问题才需要回到人这里。

### 一个适合起步的例子

选择已有记录中的一种陪伴对话失败：先定义什么行为算失败，保留几个代表性例子，再让 AI 追踪原因并做最小修复。用没有参与修改的相关记录复验，观察改善与回归。

文本回放、实际识音、播放效果和现场互动分别提供不同证据。离线完成时如实交付离线结论；现场结论需要现场材料。这样能让一段工作独立完成，也能清楚知道下一步缺什么。

### 怎样判断工作流真的改善了

观察同类任务是否更少需要重新解释背景、纠正遗漏或手动修补，同时核对交付质量。记录实际时间、人工介入及重要失败即可，无需为了衡量而建立复杂评分系统。

一次顺利案例只是初步信号。继续使用中若节省的操作被审查、返工和维护抵消，应当简化流程。

## 用 AI 推进科研

### 先明确问题与能推翻它的结果

把研究想法写成：在什么对象与条件下，某种方法预计通过什么机制改变什么结果？与什么基线比较？如果结果没有变化，或者另一解释也能解释变化，下一步如何判断？

AI 可以帮助整理研究问题、查找原始文献、检查设计、实现分析和寻找反例。问题是否重要、资源是否值得投入、结论能否承担，仍需要研究者判断。

### 按证据推进

1. **定位已有工作。** 核对原始论文、任务定义、数据条件和方法，识别与当前问题真正相关的差距。无法取得全文时标明阅读范围。
2. **建立可比较的基线。** 优先复用可用实现，固定必要的版本、输入和测量口径。
3. **做能区分解释的实验。** 根据问题选择对照、消融、误差分析或其他适合的方法，不机械要求每次全做。
4. **保留独立验证材料。** 需要评估泛化时，把用于选择方案、调参和最终评估的材料分清，避免反复查看最终评估结果再调方案。
5. **保存可复现的信息。** 原始输入、处理方法、关键参数、运行版本与失败情况应能对应结论。
6. **按证据写结论。** 样本、条件、统计口径、替代解释和未验证范围紧邻主张；负结果也可以指导停止或转向。

对于“机器人交互是否改善体验”，先明确体验由谁、在什么场景、以什么方式判断。系统能运行、能生成回复或单次演示顺利，分别只能支持相应层面的结论。涉及人的研究设计按实际课题与所在机构要求制定。

### 防止 AI 把科研变成材料生产

文献表、图表和论文草稿只有在服务研究问题时才值得继续扩充。每轮工作结束，检查多了什么可复核的知识、哪个解释被排除、什么决定因此改变。没有新增证据时，优先重新检查问题和方法。

## 用 AI 提高认知

以下是可试行的学习安排，不把它们写成原文已经验证的教育结论。

### 先留下自己的判断

遇到值得深入的问题，先简短写下自己的解释、预测和不确定处，再让 AI 检查。这样可以看见自己的判断具体在哪一步改变，避免读完流畅答案后误以为原本就会。

### 让解释接受检验

学完一个概念后，尝试解释它的机制、适用条件和一个反例，再处理一个表面不同的新案例。AI 的反馈应针对具体错误，必要时回到原始材料核对。

### 建立判断更新记录

在已有笔记中留下“原判断—依据—新证据—更新后的判断”。记录真正改变决定的事项，不追求每天堆积复盘文字。对重要预测，可以先写下条件与预期，事后再对照实际结果。

### 跨学科学方法

例如，把系统故障看作测量问题时，需要讨论测量对象与误差；把交互失败看作使用者体验问题时，需要看真实操作和反馈；把实验改进看作因果问题时，需要考虑对照与替代解释。只有能改变分析或验证的借用才值得保留。

## 可直接使用的提示词

模板按需选用，方括号替换为具体信息。效果来自目标、材料、工具与反馈的配合，文字本身不保证成功。

### 1. 日常任务的短版

```text
我要达到的结果是：[具体变化]。
完成时我应能检查到：[可观察结果]。
现有材料和约束：[必要内容]。
请在这个范围内完成实施与必要验证，发现问题继续修复；最后给出结果、证据和仍影响使用的未知。
```

适合目标清楚、已有相关材料的任务。小修可以缩成一句话。

### 2. 把模糊想法变成可实施任务

```text
我想做：[想法]，服务的实际对象和场景是：[对象、场景]。
先结合现有材料，把它整理成一个值得完成、可以验收的目标。
指出最关键的未知，以及能帮助决定路线的最小验证。
复用已有能力；在已明确的范围内先推进，不扩大为新的系统。
如果我指定的方法妨碍目标，请用具体依据说明，并给出更直接的方案。
```

适合项目起步和方向尚未定型时使用。

### 3. 要求更深入的方法

这个模板受原文的专业方法提示启发，补充了范围与投入判断。[原文](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/)

```text
针对这项任务：[任务]，检查当前方法还有什么重要缺口。
说明值得采用的专业方法、它需要的原始材料和工具，以及什么外部结果能判断它有效。
只补会改变结论或交付质量的部分；说明新增成本，已有充分证据的地方停止扩展。
```

### 4. 把科研想法变成可检验设计

```text
研究问题：[问题]。
已有材料、基线与资源：[材料]。
请明确任务对象、适用条件、主要假设、替代解释与评价方式。
设计最小但足以区分主要解释的实验，说明各类结果分别支持什么、不能说明什么，以及怎样决定继续或停止。
区分需要新采集的数据与已有材料，指出可能的数据泄漏或比较不公平。
不要假设尚未取得的实验结果，也不要替我宣称创新已成立。
```

### 5. 让文献调研服务决定

```text
我要决定：[具体研究或技术问题]。
请优先查原始论文、官方实现和数据说明，按任务、条件、方法、结果与限制比较真正相关的工作。
给出直接来源，区分已读全文、只读摘要和无法核实的内容。
最后说明：哪些信息足以支持当前决定，什么关键证据仍然缺失，以及最值得做的验证。
不为凑数量补文献，不虚构引用和结果。
```

### 6. 挑战一个重要判断

```text
当前判断：[判断]。
依据：[原始证据与推理]。
请找出最可能影响结论的假设与替代解释，给出可检查的反证。
既检查这个判断，也检查你提出的反对意见。
按现有条件选一个最能区分解释的下一步，说明不同结果会怎样改变判断；不强行凑反对意见。
```

### 7. 学懂一个概念

```text
我想掌握：[概念]，已有基础：[基础]，准备应用在：[场景]。
先用一个具体例子解释关键机制与适用边界，再给一个需要我预测结果的问题，等我回答后针对错误反馈。
随后用一个不同场景检查我是否能迁移应用。
涉及公式时解释变量、假设与必要推导；不要因我表示看懂就认定我已经掌握。
```

如果只是需要立即查一个事实，直接询问即可，不必启动教学流程。

### 8. 控制探索投入

```text
目标：[有挑战的目标]。
本轮范围、可用资源和预算：[边界]。
先检查现有方法的瓶颈，再选最有希望的方向开展验证。
每次尝试保留足以判断结果的信息；同类尝试不再增加证据时换方法。
达到完成条件、触及预算或遇到当前无法解除的阻断时，交付实际发现、限制和下一步依据，不把未证明的目标写成完成。
```

### 9. 复盘自己的 AI 工作方式

```text
以下是本轮任务的目标、实际结果、人工介入、耗时和失败：[记录]。
请判断哪些做法确实改善了结果，哪些只是增加操作与材料。
找出最值得保留的一项做法和最值得删除的一项负担，并说明依据。
区分一次案例与稳定规律；证据不足时给出下一次应观察什么，不直接新增全局规则。
```

## 从一次小实验开始

选择一个反复出现、可以离线验证的问题，先记录当前处理方式。按上述约定交给 AI 一段完整工作，检查结果，再观察同类任务是否仍然有效。

可以在现有笔记里只记这些内容：

```text
本次目标与完成条件：
最关键的未知：
实际结果与证据：
人工介入及重要失败：
投入与维护负担：
下一次保留、修改或停止什么：
```

先验证一条流程。网页规划与本地执行需要第二视角时，沿用 [[ChatGPT网页规划与Codex执行协作流程]]，只传递相关事实、最终取舍和证据需求；没有重要疑点的小任务直接完成。

## 配置应当怎样支持这些做法

全局规则保留稳定习惯与边界，项目规则保留项目事实和验收标准，具体任务提供本轮目标与材料。重复且已证实有效的做法才沉淀为工具或 Skill。

OpenAI 的配置建议也强调缩小规则适用范围、按需加载技能，以及明确完成与停止条件；这支持采用轻量入口，具体效果仍需检查本机加载和真实任务。[官方说明](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)

本机本次检查与改动见 [[本机AI工作流审计与调整 - 2026-10-24]]。文件同步、指令加载、任务行为和长期收益分别判断。

## 使用时保留的判断

- 高目标配合可检验标准和预算；反复催促模型不能补足缺失证据。
- 多个模型可以帮助发现遗漏，共同认可仍需外部反馈支持。
- 不把每项工作都扩成多 Agent、全套科研或新系统。
- 明确需要的作品形式、个人审美或创作表达应当保留，不为追问更高目标擅自替换。
- 定期用实际任务检验规则与工具；收益不足的做法可以删去。
