# 开源工具多 Agent 共享配置

本轮将 REA 与 text-to-cad 接入 Codex、Claude Code、Antigravity、DSH。REA 提供软件制品分析入口；text-to-cad 补充精确尺寸建模与 STEP 导出。其他候选项目按已有工具的覆盖程度保留或暂缓安装。

本笔记记录 2026-10-13 的安装和验证结果。候选项目对照采用本次调研于 2026-10-12 核对的本机基线，版本和路径随升级可能改变。项目热度属于选择线索，不作为重复安装的理由。

- IDE 与 CLI 读的不是同一个文件。只写 `mcp.json` 时 `qodercli mcp list` 报“无配置”，会话启动透传的 `mcpServers` 也会是空；只写 `settings.json` 则 IDE 的 MCP 面板看不到。两处必须同源投影。
- Qoder 原样透传 `env`，不展开 `${VAR}`。`glm-vision` 只声明变量名且本机未设 `GLM_API_KEY`，因此没有投影给 Qoder。

### 调研结论：共享基地不是同构配置

1. **AGENTS.md 适合做跨端指令入口**。它是开放 Markdown 格式，Codex、Cursor、VS Code、Aider 等端都读；目录树中最近的文件优先。各端仍可用自己的入口名（`CLAUDE.md`、`GEMINI.md`、`.cursor/rules/*.mdc`），但正文只维护一份。参考：<https://agents.md/>。
2. **Agent Skills 是开放格式，发现路径由宿主决定**。`SKILL.md` 的目录约定和 frontmatter 可以共享，但 Claude、Codex、OpenCode、Qoder、Trae 的扫描位置不同。能原生读 `~/.agents/skills` 的端就不复制，读不到的端才投影。参考：<https://agentskills.io/>、<https://opencode.ai/docs/skills/>。
3. **MCP 是协议标准，不是配置标准**。同一个 stdio 服务在 Codex 是 TOML、在 Claude/Qoder/CodeBuddy 是 `mcpServers` JSON、在 OpenCode 是 `mcp` 与 `type: local` 数组。正确做法是从 `servers.yaml` 渲染到各端原生格式，而不是复制同一份 JSON。参考：<https://opencode.ai/docs/mcp-servers/>、<https://docs.qoder.com/zh/cli/mcp-reference>。
4. **社区实践同样倾向“共享知识 + 端适配”**。强制同构会带来重复副本、过期配置和凭据扩散；各端保留模型、权限、插件和加载时机的差异，反而更容易把共享资产用起来。这也与最初“基地供各 Agent 借鉴参考”的意图一致。多宿主安装经验可参考：<http://www.chenxutan.com/d/7515.html>。

## 验证结果和边界

**FACT：** 从四份原生配置提取命令，分别完成 REA/CAD 共 8 次 MCP 初始化、工具枚举及业务调用。Claude Code 原生 CLI 显示两个服务均 Connected；Codex CLI 可读取 CAD 配置，Antigravity CLI 可列出两项服务。
