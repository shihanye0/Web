# LIBERO-Para：VLA 模型释义鲁棒性的诊断基准与评估指标

> [!abstract] 一句话结论
> 论文通过在固定机器人场景和任务目标下，仅改变指令的动作表达与物体指称，构造 LIBERO-Para，并结合 PRIDE 与 Near-GT/Far-GT 轨迹诊断，证明多种 VLA 在语义保持的释义指令下会显著掉点；物体指称变化通常比动作表达变化更危险，动作与物体变化还会产生超加性交互。

> [!note] 阅读定位
> 这篇论文最适合用作课题的“问题存在性与实验设计基线”，而不是直接当作完整的攻击方法。它回答了“正常改写能否让 VLA 失败”，但没有完整回答“如何自动搜索最有效的攻击”“攻击如何定向改变行为”以及“模型内部为什么会失败”。

## 1. 研究问题

### 1.1 论文要回答什么

- 研究对象：使用视觉、语言和动作模块完成机器人操作的 VLA 模型。
- 核心问题：当机器人场景、物体布局、任务目标和执行条件均不变，只把原始指令改写成语义保持的自然表达时，VLA 的任务成功率是否仍然稳定？
- 诊断问题：如果释义导致失败，失败更像是底层执行误差，还是语言到任务目标/动作规划的偏离？
- 指标问题：只报告原始指令与释义指令的成功率，能否区分“简单释义成功”和“困难释义也成功”？
- 重要性：VLA 往往在有限的机器人数据上微调，可能记住训练数据中的固定指令形式；同一任务的语言表达变化因此成为部署可靠性的重要测试。
- 语义边界：研究对象不是“把指令改成另一条任务”，而是在用户意图、场景指称和目标行为不变的前提下，只改变表达形式。例如，`Put the bowl on the stove` → `Place the bowl on the cooktop` 仍要求操作同一个碗和炉灶；若把 `bowl` 换成 `plate`，任务目标已经改变，不应再作为语义保持型攻击样本。
- 研究意义：对 VLA 攻击而言，关键不是诱导模型执行另一条合法指令，而是在任务没有改变时，让模型偏离原本应完成的任务。

### 1.2 现有方法哪里不足

- 既有机器人基准通常以任务成功率为主，不能单独隔离语言表达变化。
- 许多评估只使用原始或固定模板指令，语言分布与任务分布同时变化，难以判断失败来自语言还是任务本身。
- 现有释义研究可能只改变动作表达，或只做随机同义替换，缺乏对动作轴、物体轴及其组合效应的控制。
- 传统指标可以计算文本相似度，但不一定反映“模型成功处理了多难的释义”。
- 过去的语言改写有时只是多模态扰动中的一个附属维度，或与会改变任务意图的任务级语义变化混在一起；这会削弱对“纯表达变化”影响的归因。
- 增加训练任务的种类不等于增加语言表达的种类：`task diversity` 与 `linguistic diversity` 是不同的数据属性，前者增加并不自动带来释义鲁棒性。
- `INFERENCE`：论文把研究空白从“模型能不能完成任务”推进到“模型能不能在任务不变时理解不同的自然表达”。

### 1.3 论文不回答什么

- 没有证明某一种模型内部表示一定采用了关键词匹配；论文只观察到物体词变化与较大性能下降相伴。
- 没有证明所有释义样本都具有绝对相同的语义。人工标注显示总体一致性较高，但严格阈值下仍有分歧。
- 没有研究经过释义数据增强、对比学习或指令归一化训练后的防御效果。
- 没有系统研究真实机器人上的物理执行风险，也没有证明仿真中的失败比例会原样迁移到现实。
- 没有把“导致失败”形式化为自动攻击搜索或定向行为重定向目标。
- 没有给出模型注意力、中间表示、目标选择 logits 或 action expert 内部状态的因果证据。
- 没有穷尽多轴叠加、跨语言、跨说话者、长上下文、视觉遮挡和对话历史等条件。

## 2. 核心概念与术语

| 概念 | 本文含义 | 与相近概念的区别 | 对我的研究的意义 |
|---|---|---|---|
| Paraphrase robustness | 指令改写后仍完成同一机器人任务的能力 | 不是一般 NLP 文本相似度，也不是只看语言模型输出 | 是“语义保持型自然指令攻击”的问题基础 |
| Action axis | 改变动作在语言中的表达方式 | 不改变被操作对象和任务目标 | 可作为攻击因素和控制变量 |
| Object axis | 改变物体指称方式 | 不改变动作意图和场景中的目标对象 | 论文中通常是更强的脆弱因素 |
| Surface-level matching | 依赖训练中见过的关键词或固定表达模式 | 不等于真正把词映射到当前场景对象 | 物体词变化导致失败时的待验证解释 |
| Semantic grounding | 将语言概念对应到当前场景中的具体物体、动作和状态 | 不只是文本相似，而是语言与环境实体/行为的对齐 | 区分表层匹配与稳健任务理解的关键 |
| Binary success rate | 每条 rollout 成功记为 1、失败记为 0，再求平均 | 能反映总体完成率，但不能表示改写难度 | 需要和 `PD`、`PRIDE` 及失败类型联合使用 |
| Contextual substitution | 依赖当前语境才自然或准确的物体替换 | 不是脱离场景的字典同义词 | 可用于测试场景约束下的语义扎根 |
| Habitual substitution | 更常见、更习惯化的同义表达替换 | 与上下文特定表达相对 | 可区分词汇熟悉度与真正的目标理解 |
| Compositional variation | 同时改变动作轴与物体轴 | 不等于只增加样本量，而是改变因素组合 | 是研究交互攻击的直接起点 |
| Super-additive interaction | 组合变化造成的性能下降超过两个单轴下降之和 | 不是简单的加法效应 | 可用于证明攻击因素之间存在协同脆弱性 |
| Task diversity / linguistic diversity | 前者是任务、场景或物体配置的多样性，后者是同一任务的表达方式多样性 | 增加任务数量不等于增加语言覆盖 | 是解释训练数据为何未自动提升释义鲁棒性的关键 |
| PD | 原始指令与释义指令的语言偏差/距离 | 可以对成功和失败样本都计算 | 衡量扰动难度，不能单独当作攻击成功 |
| PRIDE | 在成功条件下保留释义难度的鲁棒性指标 | 失败样本被置为 0 | 衡量模型“成功处理了多难的释义” |
| Near-GT | 失败轨迹仍接近成功轨迹 | 不能直接等同于纯执行故障 | 可作为轨迹层面的失败分类 |
| Far-GT | 失败轨迹明显偏离成功轨迹 | 不能直接等同于已证明的内部规划因果 | 可提示任务识别或规划层面异常 |

### 2.1 表层匹配与语义扎根

- **表层匹配（surface-level matching）**：模型主要依赖训练时见过的关键词、词形或固定表达模式，将语言形式直接关联到动作输出。
- **语义扎根（semantic grounding）**：模型把语言中的词或概念正确对应到当前环境中的具体对象、动作和状态。例如看到 `stove` 或语境中等价的 `range`，都能定位场景中的同一个炉灶。
- `INFERENCE`：物体指称变化比动作变化更容易造成失败，支持“物体相关语言映射可能不稳健”这一解释；但它不能单独证明模型内部确实只做关键词匹配，也不能证明不存在真正的 object grounding。

## 3. 论文贡献

1. **受控基准：LIBERO-Para**
   - 类型：benchmark / 数据构造流程。
   - 基于 LIBERO-Goal，在固定场景、物体布局和任务目标下，只改变指令表达。
   - 将动作表达和物体指称拆成两个变化轴，并加入二者组合条件。

2. **诊断指标：PRIDE**
   - 类型：task-aware robustness metric。
   - 将文本释义距离与任务成功条件结合，避免只看成功率或只看文本距离。
   - 进一步拆出关键词相似度和结构相似度，帮助解释释义难度来源。

3. **失败轨迹诊断**
   - 类型：post-hoc trajectory analysis。
   - 用失败轨迹与成功轨迹的距离，将失败分为 Near-GT 和 Far-GT。
   - 论文据此报告大部分失败更接近规划/任务识别偏离，而非局部执行误差。

4. **跨设置实证发现**
   - 多个 VLA 配置、不同模型规模、架构、训练数据范围和微调方式均出现释义脆弱性。
   - 物体变化通常比动作变化更难，动作与物体组合变化出现超加性下降。

## 4. 方法主线

```text
固定任务与场景 → 构造语义保持释义 → 人工语义验证 → 按动作/物体轴组织单轴与组合条件 → 运行多种 VLA → 计算 SR、PD、PRIDE → 分析 Near-GT/Far-GT → 跨环境复核
```

### 4.1 输入、变量与控制条件

- 输入：LIBERO-Goal 任务、原始语言指令、由生成流程得到的释义指令、机器人视觉观测和动作执行环境。
- 被改变的变量：指令中的动作表达、物体指称，或二者的组合。
- 被固定的变量：场景、物体布局、任务目标、机器人任务本身和评估流程。
- 对照组：原始指令；同时设置 Action-only、Object-only 和 Compositional 条件。
- 可能的混杂因素：释义自然度、指令长度、词频、生成模型偏差、人工标注者对语义的理解差异、基准任务本身噪声和模型随机种子。
- 关键设计原则：一次尽量只操纵一个语言因素，再比较两个因素的组合是否超出单轴效应之和。

### 4.2 Benchmark 构造

- 基础任务：LIBERO-Goal。
- 变化轴：
  - `Action axis`：10 类语言变化，包括 `None`、`Addition`、`SP-contextual`、`SP-habitual`、`Coordination`、`Subordination`、`Need-statement`、`Embedded imperative`、`Permission directive`、`Question directive` 和 `Hint`。
  - `Object axis`：3 类变化，包括 `Addition`、`Same-polarity substitution (contextual)` 和 `Same-polarity substitution (habitual)`。
- 变化单元格：10 个动作单轴、3 个物体单轴、30 个动作×物体组合，共 43 个变化单元格；原始指令作为独立对照。
- 数据规模：共 4,092 条释义指令，平均每类约 100 条。
- 数据流程：`generator → verifier → merger → merged-set re-verifier`。
- 生成/验证工具：附录报告使用 Gemini 2.5 Pro 参与生成与验证流程；这属于数据流程组成部分，不应理解为语义等价性的自动证明。
- 直观上，动作变化又可按三层理解：`Lexical` 是换动作词或增加修饰，`Structural` 是改变并列/从属等句法组织，`Pragmatic` 是用需求、请求、问题或暗示间接表达操作意图。
- 物体变化包括：在名称上增加符合场景的描述、使用依赖当前场景的替代称呼（`contextual`），以及使用日常语言中较常见的近义称呼（`habitual`）。其中，新增描述若引入场景中不存在的属性，可能改变指称范围，不能再视为安全释义。

### 4.3 语义验证

- 从完整 benchmark 抽取 5%，共 205 条样本进行人工判断。
- 15 名标注者独立判断原始指令与释义是否导致相同成功行为。
- Gwet's `AC1 = 0.854`。
- 多数标准 `≥8/15`：204/205 条通过。
- 严格标准 `≥12/15`：183/205 条通过。
- `FACT`：整体标注一致性较高，但严格标准下仍有 22 条未达到阈值。
- `INFERENCE`：建议式、陈述式和间接言语行为的语义保持更依赖语境，不能只靠词面相似度保证。
- `UNRESOLVED`：未验证的 95% 样本不能被表述为逐条都获得了人工语义等价确认。

### 4.4 评价指标

| 指标 | 计算/定义 | 测量对象 | 解释边界 |
|---|---|---|---|
| `SR` | 任务成功率 | 实际任务完成表现 | 不说明失败是语言、规划还是执行原因 |
| `ΔSR` | 原始 SR 与释义 SR 的差值 | 释义导致的性能损失 | 受原始任务难度和基准噪声影响 |
| `S_K` | 对原始/释义关键词嵌入做最大余弦匹配后取平均 | 关键词层面的相似度 | 不能完整表示句法和语用变化 |
| `S_T` | 基于句法树编辑距离的结构相似度 | 结构层面的相似度 | 依赖解析质量，不能完整表示语义 |
| `PD` | `1 - (αS_K + (1-α)S_T)`，`α=0.5` | 释义语言偏差/难度 | 可对失败样本计算，不等于任务成功 |
| `PRIDE` | 成功时为 `PD`，失败时为 0 | 成功处理的释义难度 | 不是单纯“越高越鲁棒”；需结合 SR 解释 |
| `Near-GT/Far-GT` | 失败轨迹与成功轨迹的 DTW 距离分类 | 轨迹层面的失败形态 | 是行为诊断，不是内部因果证明 |

#### 指标的直观读法

- `SR` 本质是二元成功率：对每条 rollout 记 `success=1`、`failure=0`，再求平均。它适合回答“总体完成了多少”，但不能区分模型只会处理简单改写，还是也能处理困难改写。
- `S_K` 只比较动作词、物体名等任务关键词。对原始指令中的每个关键词，在释义指令中寻找向量空间里最相似的关键词，再对这些最大相似度取平均；因此它比 BLEU 更关注“决定任务的词是否被保留”，但仍不等于任务语义相同。
- `S_T` 比较两条指令的依存句法树。节点对应词，但比较标签主要使用词性（POS）和依存关系，尽量把 `drawer → cabinet` 这类词汇替换与句法组织变化区分开。
- `PD` 由 `S_K` 和 `S_T` 的加权相似度转换而来；`PD` 越高表示语言形式变化越大，不表示任务语义已经改变。语义保持要靠数据构造和验证流程保证，而不是靠 `PD` 本身保证。
- `PRIDE` 是“语言变化难度 × 任务成功”的联合读数：成功时保留 `PD`，失败时置零。因此 `PRIDE` 高表示模型成功处理了更难的释义，而不是攻击效果更强；攻击研究仍需同时报告 `PD`、SR/失败率和失败类型。

## 5. 证据与实验矩阵

### 5.1 实验设置

- 主要环境：LIBERO-Para，建立在 LIBERO-Goal 之上。
- 外部复核环境：CALVIN-Para。
- 模型范围：7 种 VLA 配置，模型规模约 `0.6B–7.5B`，覆盖 4 类架构家族。
- 训练设置比较：不同任务训练数据范围，以及 `π0.5 Full` 与 `π0.5 Expert-only` 两种微调策略。
- 主要观察指标：原始/释义任务成功率、成功率下降、PRIDE、语言偏差、失败轨迹类别。
- 统计方式：按释义单元格和模型汇总；PRIDE 与成功率之间使用 Pearson 相关分析。
- `FACT`：论文也报告了不同随机种子的分析，并指出 PRIDE 在所分析的 30 个模型-条件组合中排名第一。
- `UNRESOLVED`：整理时不把“跨设置观察到相关性”扩展为对所有 VLA、所有任务和所有语言的普遍定理。

### 5.2 实验矩阵

| 实验 | 比较什么 | 观察指标 | 关键结果 | 支持的结论 |
|---|---|---|---|---|
| 原始 vs. 全部释义 | 固定任务下语言形式变化 | SR、PRIDE | 7 种配置均下降 | 释义脆弱性不是单一架构现象 |
| Action-only | 只改变动作表达 | SR、ΔSR、PRIDE | 平均 SR 约 `82.1%`，较原始下降 `12.9 pp` | 动作间接化和句式变化会造成额外负担 |
| Object-only | 只改变物体指称 | SR、ΔSR、PRIDE | 平均 SR 约 `78.6%`，较原始下降 `16.4 pp` | 物体指称变化通常更敏感 |
| Compositional | 同时改变动作与物体 | SR、ΔSR | 平均 SR 约 `52.4%`，下降 `42.6 pp` | 两个语言因素存在超加性交互 |
| 训练数据范围 | `OFTgoal` 与 `OFTmixed` | 释义下降幅度 | 约 `33.2 pp` vs. `32.4 pp` | 任务多样性不等于语言多样性 |
| 微调策略 | `π0.5 Full` 与 `π0.5 Expert-only` | 原始 SR、释义 SR、PRIDE | Full：`97.6%→71.4%`；Expert-only：`78.6%→39.1%` | 联合微调更强，但不能消除释义脆弱性 |
| 语言距离指标 | PRIDE 与通用 NLP 指标 | 与 SR 的相关性 | PRIDE 最高达到 `|r|=0.802` | task-aware 指标更能反映成功处理的释义难度 |
| 轨迹诊断 | Near-GT 与 Far-GT | 失败比例 | 各模型 Far-GT 约 `79.5%–95.5%` | 失败更多表现为明显轨迹偏离 |
| CALVIN-Para | 跨 benchmark 复核 | 原始/释义 SR、Far-GT | RoboFlamingo：`92.3%→53.1%`；FLOWER：`99.7%→58.3%` | 现象不只出现在 LIBERO |

### 5.3 关键结果

#### 结果一：释义脆弱性具有跨模型普遍性

- `FACT`：LIBERO-Goal 到 LIBERO-Para 的成功率下降范围为 `22.8–51.9 pp`。
- `FACT`：模型规模、架构家族、训练数据范围和微调方式不同，仍然普遍出现下降。
- `INFERENCE`：单纯更换架构、增大参数量或增加任务种类，并不能自动获得语言表达鲁棒性。
- `UNRESOLVED`：论文没有隔离“模型视觉语言骨干”“动作专家”“数据配比”和“解码策略”各自的因果贡献。

#### 结果二：物体变化通常比动作变化更危险

- `FACT`：Object-only 平均成功率低于 Action-only，平均下降约为 `16.4 pp` 对 `12.9 pp`。
- `FACT`：较难条件包括 `SP-habitual × Question`，平均 PRIDE 约 `0.42`；`SP-habitual × Hint` 的成功率约 `30.4%`。
- `INFERENCE`：模型对物体指称的词汇变化可能比对动作句式变化更不稳定。
- 直观理解：如果 `stove → cooktop` 这类表达变化就足以影响目标选择，说明模型可能没有稳定地把不同词语映射到同一个场景对象；这是一条机制线索，不是对内部表示的直接观测。
- 不能直接写成：模型已经被证明只做表层关键词匹配，或已被证明不存在真正的 object grounding。

#### 结果三：动作与物体变化存在超加性交互

- `FACT`：单轴下降之和约为 `12.9 + 16.4 = 29.3 pp`。
- `FACT`：组合条件下降约 `42.6 pp`，高于单轴效应之和。
- `INFERENCE`：动作表达和物体指称不是两个完全独立的语言噪声源；当两者同时变化时，模型的语言到任务映射可能出现协同失稳。
- 对本人课题的价值：攻击实验不能只报告单个扰动的成功率，应显式检验组合因素是否产生 interaction。

#### 结果四：PRIDE 不是普通文本相似度

- 关键词相似度：
  \[
  S_K(O,P)=\frac{1}{n}\sum_i \max_j \cos(e(o_i),e(p_j))
  \]
- 结构相似度：
  \[
  S_T(T_O,T_P)=1-\frac{TED(T_O,T_P)}{|T_O|+|T_P|}
  \]
- 释义距离：
  \[
  PD=1-\left(\alpha S_K+(1-\alpha)S_T\right),\quad \alpha=0.5
  \]
- PRIDE：
  \[
  PRIDE=\begin{cases}PD,&\text{任务成功}\\0,&\text{任务失败}\end{cases}
  \]
- `FACT`：PD 可对所有样本计算；PRIDE 只保留成功样本的释义难度，失败样本置 0。
- 正确解读：PRIDE 越高，表示模型成功处理了越难的释义；它不是脱离 SR 后的“纯鲁棒率”。
- 对攻击研究的报告建议：同时报告 `PD`、SR/失败率、PRIDE 和 Near-GT/Far-GT，避免把“改写很难”和“攻击很成功”混为一谈。

#### 结果五：失败主要表现为 Far-GT

- 作者使用末端执行器 `EEF (x,y,z)` 轨迹。
- 用成功轨迹的平均值构造伪 `GT`，再以 DTW 距离衡量失败轨迹与成功行为的接近程度。
- 以成功轨迹的最大距离设置阈值：接近阈值为 Near-GT，明显超过阈值为 Far-GT。
- `Pseudo-GT` 的直观含义是：收集同一任务下的成功轨迹，对齐后求平均，得到一条参考行为轨迹；`DTW` 允许不同执行速度在时间轴上进行非线性对齐。阈值可写成 `τ = max(DTW(T_success, T_Pseudo-GT))`，失败轨迹距离不超过 `τ` 归为 Near-GT，超过 `τ` 归为 Far-GT。
- `FACT`：各模型 Far-GT 占失败比例约 `79.5%–95.5%`。
- `FACT`：CALVIN-Para 中 RoboFlamingo 和 FLOWER 的 Far-GT 分别为 `93.4%` 和 `97.1%`。
- `INFERENCE`：许多失败不是“动作大致正确但最后没有完成”，而是较早阶段已经走向不同的行为轨迹。
- 机制边界：Far-GT 是轨迹层面的行为分类，不能单独证明失败发生在模型内部的规划模块；还需要中间状态、目标选择或干预实验。

### 5.4 论文最重要的证据链

```text
控制任务与场景
→ 只改变语义保持的语言形式
→ 通过人工抽样验证同一成功行为
→ 多模型重复出现 SR 下降
→ Object-only 通常比 Action-only 更差
→ Action×Object 下降超过单轴之和
→ 失败轨迹多数为 Far-GT
→ 支持“语言到任务映射是脆弱的”这一行为层判断
```

## 6. 结果解释与失败机制

### 6.1 论文声称的发现

1. VLA 的释义脆弱性跨架构、规模、训练数据范围和微调策略普遍存在。
2. PRIDE 比传统 SR 或单一文本指标更能区分模型处理简单与困难释义的能力。
3. 物体层面的语言变化通常是主要瓶颈，动作间接表达是额外因素。
4. 动作和物体同时变化会产生超加性交互。
5. 释义导致的失败多数在轨迹层面明显偏离成功轨迹。

- 训练设置的启发：`OFTmixed` 虽然包含更多任务，释义后的下降幅度仍与 `OFTgoal` 接近；这支持“任务多样性不等于语言多样性”的判断。若要改善释义鲁棒性，训练数据中需要显式覆盖同一任务的多种自然表达，而不是只增加任务数量。

### 6.2 结果真正证明了什么

- 直接证明：在论文所覆盖的任务、模型和释义集合中，保持任务目标不变的语言变化足以导致显著性能下降。
- 直接证明：变化轴之间的性能损失并非总是可加的，组合条件需要单独测量。
- 直接证明：使用轨迹距离分类时，大部分失败属于 Far-GT。
- 有限支持：物体指称变化可能是比动作表达变化更敏感的测试因素。
- 不能直接证明：模型内部使用了某种具体匹配机制；不能直接证明真实机器人部署会有相同下降；不能直接证明所有样本都严格语义等价。
- 证据强度判断：行为结论较强，机制结论中等，内部因果结论不足。

### 6.3 失败案例或机制诊断

| 诊断层 | 论文观察 | 合理解释 | 不应过度推出的结论 |
|---|---|---|---|
| 任务结果 | 释义后 SR 下降 | 语言形式影响任务完成 | 不等于所有失败都由语言理解引起 |
| 语言因素 | Object-only 通常比 Action-only 更差 | 物体指称可能是敏感瓶颈 | 不等于已证明 object grounding 内部失效 |
| 组合效应 | 组合下降超过单轴之和 | 存在交互或协同失稳 | 不等于已经识别交互的神经机制 |
| 轨迹形态 | Far-GT 占多数失败 | 任务识别/规划偏离的行为迹象 | 不等于直接观测到 planning module 的错误 |
| 跨环境复核 | CALVIN 也下降 | 现象具备一定外部复核 | 不等于跨所有机器人和现实场景普遍成立 |

## 7. 局限、风险与可复现性

### 7.1 作者明确或论文可直接看到的局限

- 主要实验仍依赖仿真 benchmark，真实机器人上的执行噪声、视觉误差和安全约束未被充分验证。
- 语言变化类型虽然覆盖动作、物体和组合，但每个轴内部仍是有限类别，不能代表全部自然语言现象。
- 论文主要做评估和诊断，没有系统评估释义数据增强、鲁棒训练或防御方法。
- 机制分析停留在成功率和轨迹形态，未深入模型内部表征与因果干预。
- 语义验证使用抽样人工标注，不能自动保证完整数据集中的每一条指令都无歧义。

### 7.2 设计风险

- **语义风险：** “同一成功行为”可能允许不同但合理的执行路径；标注者分歧可能集中在间接言语行为、Hint 和建议式表达。
- **生成风险：** LLM 生成的表达可能同时改变礼貌、语气、信息量、动作时序或隐含前提，造成非目标因素变化。
- **指标风险：** PRIDE 把失败样本置为 0，会把“高语言难度导致失败”和“低语言难度也失败”折叠到同一结果空间，需配合 PD 和 SR 解读。
- **轨迹风险：** 平均成功轨迹构造的伪 GT 可能掩盖多模态的合理成功轨迹；DTW 阈值也可能受到轨迹长度、速度和控制器差异影响。
- **归因风险：** Far-GT 只能说明行为偏离，不足以独立区分 object grounding、task identification、目标选择和 action generation。
- **外部有效性风险：** LIBERO 与 CALVIN 的任务分布、语言风格和机器人 embodiment 有限，不能自动代表现实部署。
- **统计风险：** 逐单元格均值和模型排序不等同于对所有任务、所有模型的总体效应；应保留任务级和种子级分布。

### 7.3 复现清单

- [ ] 固定相同的基础任务、场景、物体布局和初始状态。
- [ ] 获得或重建 generator、verifier、merger 和合并后 re-verifier 流程。
- [ ] 保存每条原始指令、释义指令、变化轴标签和生成提示。
- [ ] 复核人工语义验证的抽样比例、标注协议、阈值和标注者一致性。
- [ ] 逐模型、逐任务、逐随机种子记录原始与释义 rollout。
- [ ] 同时计算 SR、ΔSR、PD、PRIDE 和 Near-GT/Far-GT。
- [ ] 报告失败轨迹阈值、DTW 细节、轨迹坐标、长度处理和多成功轨迹聚合方式。
- [ ] 复核 Object-only、Action-only 和组合条件的样本数是否平衡。
- [ ] 在至少一个不同 benchmark 或不同任务分布上复核现象。
- [ ] 不把一次成功复现写成真实机器人、所有模型或所有语言条件的普遍结论。

## 8. 论文做了什么 / 没做什么

| 做了什么 | 没做什么 | 这对研究边界的影响 |
|---|---|---|
| 固定任务和场景，独立改变动作/物体语言因素 | 没有穷尽所有自然语言变化 | 可作为受控起点，不能作为完整语言覆盖 |
| 建立单轴与动作×物体组合矩阵 | 没有研究更多轴的高阶交互 | 可以继承 factorial 设计，但需增加新因素或机制问题 |
| 用人工抽样验证语义保持 | 没有逐条人工证明整个数据集 | 需要在新攻击数据中加强逐样本语义门禁 |
| 报告 SR、PD、PRIDE | 没有用单个指标解决所有归因问题 | 新工作应联合报告效果、难度和失败类型 |
| 用轨迹 DTW 分 Near-GT/Far-GT | 没有直接观测模型内部规划状态 | 轨迹诊断可继承，但要补表征/干预证据 |
| 在 LIBERO 和 CALVIN 上复核 | 没有真实机器人或大规模跨 embodiment 验证 | 跨环境迁移是自然的后续问题 |
| 证明释义会造成失败 | 没有自动搜索最有效的攻击或定向目标 | 仅做更多同义词扩展会与本文高度重叠 |
| 讨论 object-level vulnerability | 没有评估防御或语言增强训练 | 攻击-防御对照可形成明确增量 |

## 9. 对我的研究的迁移

### 9.1 可以直接继承

- **问题约束：** `Natural + Semantic-Preserving + Scene-Valid + Behaviorally Effective` 四个条件同时成立。
- **扰动分类：** 采用动作轴、物体轴和组合轴，避免把所有改写混为一个黑盒集合。
- **实验结构：** 原始对照、单轴对照、组合条件、跨模型和跨任务复核。
- **交互分析：** 用单轴下降之和与组合下降比较，显式检验 super-additive interaction。
- **语义门禁：** 生成后进行结构检查、场景一致性检查、人工或多标注者语义验证，再进入攻击评估。
- **联合报告：** 同时报告扰动距离 `PD`、任务失败/攻击成功、PRIDE、轨迹偏离和失败类别。
- **诊断思路：** 先判断是 Near-GT 还是 Far-GT，再进一步区分目标选择、任务识别、规划和动作生成。
- **流程设计：** 继承 `generator → verifier → merger → re-verifier` 的数据质量流水线。

### 9.2 不能直接照搬

- 不能只把 LIBERO-Para 的指令再生成一批同义句，然后把更低 SR 称为新的攻击方法。
- 不能只替换模型、换一个仿真环境或扩大样本量，却不提出新的机制、迁移或防御问题。
- 不能把 PRIDE 直接当作攻击成功率，也不能只报告 PRIDE 不报告 PD 和 SR。
- 不能把 Far-GT 直接写成“模型规划模块被攻击成功”；需要额外的目标选择、表征或干预证据。
- 不能把人工抽样的一致性结果扩展成全部样本的绝对语义等价证明。
- 不能把“物体词替换更危险”直接推广成所有任务、所有语言和所有 embodiment 的固定规律。

### 9.3 如何避免重复

- 本文已经解决：受控地证明“语义保持改写会让 VLA 掉点”，并初步定位动作/物体因素及其组合效应。
- 仍可能重复：换同义词、换模型、换 benchmark、再报告一次成功率下降。
- 有区分度的方向：
  1. **组合式自然攻击：** 研究哪些语言因素组合最容易产生协同失稳，并建立交互效应模型。
  2. **机制定位：** 区分 object grounding、task identification、目标选择、规划和 action generation 哪一层受影响。
  3. **攻击迁移：** 测试在一个模型/任务上发现的自然指令是否能迁移到其他模型、任务和 embodiment。
  4. **攻击-防御对照：** 比较释义增强、对比学习、指令归一化或多表述训练能否消除脆弱性。
  5. **执行前预测：** 在不运行完整 rollout 的情况下，预测哪些语义保持变化最危险。
6. **定向行为偏移：** 从“让任务失败”升级为“让轨迹朝指定错误目标变化”，但必须保持场景有效和语义约束。

推荐的研究推进顺序是：

`发现鲁棒性缺陷 → 用控制变量定位敏感因素 → 分析失败轨迹 → 提出并验证失效机制 → 发展攻击或防御方法`。

这条路线比单纯继续生成更多同义句更有区分度，也能把“现象复现”推进到“机制解释和可迁移方法”。

## 10. 我的研究问题与后续实验

### 10.1 新问题

- **RQ1：** 在严格保持任务意图、场景有效性和自然性的前提下，哪些语言因素组合最容易诱发 VLA 的失败或定向行为偏移？
- **RQ2：** 语义保持型指令变化首先影响的是物体 grounding、任务识别、目标选择、规划，还是 action generation？
- **RQ3：** 在一个模型或任务上找到的自然攻击，能否迁移到不同架构、任务、embodiment 和环境？
- **RQ4：** 释义数据增强、指令归一化或多表述训练能否降低攻击成功率？代价是什么？
- **RQ5：** 能否在执行前，仅根据原始指令、释义距离和视觉场景，预测某条语言变化的危险程度？

### 10.2 待验证假设

- **H1：组合假设：** 同时改变动作表达和物体指称的自然指令，其攻击成功率高于两个单轴攻击成功率的独立组合预期。
- **H2：物体假设：** 在场景中存在多个相似或可混淆对象时，物体指称变化比动作句式变化更容易造成目标选择错误。
- **H3：机制假设：** 大多数 Far-GT 失败发生在目标选择或任务规划偏离之后，而不是单纯的末端执行误差。
- **H4：迁移假设：** 保持语义和场景约束的攻击模板可以跨模型迁移，但具体有效率会受到模型语言骨干和动作专家训练方式影响。
- **H5：防御假设：** 增加任务种类本身不足以显著提升鲁棒性；只有显式增加语言表达多样性或做指令归一化，才可能降低释义攻击成功率。

### 10.3 最小验证实验

| 假设 | 最小实验 | 成功标准 | 可能反例 |
|---|---|---|---|
| H1 | 选少量任务，构造原始、Action-only、Object-only、Action×Object 四组，固定场景和 rollout 预算 | 组合效应显著超过两个单轴效应之和，并在多个任务重复 | 组合效应仅由指令长度或自然度下降造成 |
| H2 | 每个任务设置单目标、相似物体、多目标场景，比较物体替换与动作改写 | 物体变化在相似物体条件下造成更高目标选择错误率 | 失败只在某些词频或生成模板上出现 |
| H3 | 保存完整轨迹，结合 Far-GT、目标选择日志、关键帧和动作分布 | Far-GT 先伴随目标/规划偏离，再出现执行差异 | Far-GT 只是速度、长度或控制器差异造成 |
| H4 | 在模型 A 上生成攻击候选，在模型 B/C 和不同任务上零样本测试 | 一部分候选跨模型有效，且效果不依赖单个任务 | 攻击只对生成它的模型过拟合 |
| H5 | 对同一批任务做普通任务扩展、语言扩展和归一化训练三种对照 | 语言扩展/归一化组的释义攻击成功率下降更明显 | 任务扩展已经足以解决问题，或训练造成原始性能损失 |

## 11. 我的理解与批判

- **最重要的理解：** 论文的核心不只是“换个说法会掉点”，而是把语言鲁棒性拆成可控因素，并证明组合变化的风险不能由单个因素简单外推。
- **最容易误读的地方：** `PRIDE` 不是越高就代表模型总体越鲁棒；它表示模型成功处理的释义难度，必须与 SR 一起看。
- **第二个容易误读的地方：** Far-GT 是轨迹行为分类，不是模型内部规划失败的直接观测。
- **第三个容易误读的地方：** 物体变化的较大性能下降支持“物体指称是敏感因素”，但还不足以单独证明“模型只依赖关键词”。
- **我同意的地方：** 固定场景、独立改变语言因素、加入组合条件，是研究语义保持型攻击时比无控制地生成同义句更可靠的路线。
- **我仍怀疑的地方：** 平均成功轨迹作为伪 GT 可能把多条合理成功路径压成一条；需要检查不同成功轨迹之间的多模态性，以及 DTW 阈值对分类结果的敏感度。
- **我仍需要核对的地方：** 原论文代码、完整数据生成配置、每类样本的具体分布、所有附录表格和 CALVIN-Para 的完整实验细节，应在正式复现实验前逐项核对。
- **对本人课题的优先级判断：** 第一优先级是复现一个小规模、严格语义门禁的 Action/Object/组合矩阵；第二优先级是补充目标选择与规划层证据；第三优先级才是自动搜索和跨环境扩展。

其中，最重要的是第二条：改写可以改变表达方式，但不能改变机器人应该完成的任务。
这段话强调了一个关键原则：攻击性语言改写必须与任务语义变化区分开来。 如果改写直接改变了任务目标，即使机器人失败，也不能据此证明模型对“语义保持的改写”存在脆弱性。


### 1. Morphology（形态变化）：全部排除

指单词的形态或构词变化，例如单复数、时态、情态动词和词性变化。

- 单复数变化：可能改变物体数量。
    
- 动作时态变化：可能改变时间含义。
    
- 情态动词变化：可能改变指令意图。
    
- 词性变化：例如 `pick`（拾取）变成 `picker`（拾取器），可能破坏祈使句结构或原本的指代。
    

因此，作者认为这类变化不适合用来构造受控的机器人指令改写。

### 2. Lexicon（词汇变化）：保留同极性替换，其余排除

作者保留两种替换：

- Habitual same-polarity substitution：习惯性、常见语境下的同极性词语替换。
    
- Contextual same-polarity substitution：特定语境中的同极性词语替换。
    

这里的“同极性”可以简单理解为：替换后不改变原本的肯定或否定方向，目标是保持任务含义。

其余类型被排除，原因包括：

- 拼写变化通常不能构成有意义的语言变化。
    
- 命名实体替换不太适用于以普通名词和通用动词为主的机器人指令。
    
- 格式变化要么过于简单，要么难以在保留语义的情况下应用。
    

对你的 VLA 攻击研究而言，这一类很重要：例如，把 `stove` 换成在当前场景中仍然指向同一物体的另一种合理表达，测试模型是否过度依赖固定词汇。

### 3. Lexical-syntactic（词汇—句法变化）：全部排除

这类改写同时涉及词汇与句法关系，作者认为不适合简短的机器人祈使句。

- 反极性替换：可能改变肯定与否定含义，导致任务发生变化。
    
- 综合式／分析式替换：例如用较长的描述性短语代替简洁词语，可能显得不自然。
    
- 逆关系替换（converse substitution）：涉及关系角色互换，容易让指令表达变得生硬。
    

作者的重点是：这些改写不容易做到既自然，又严格保持操作意图。

### 4. Syntax（句法变化）：保留并列与从属结构变化

作者保留两类：

- Coordination（并列结构）
    
- Subordination（从属结构）
    

其余类型排除：

- Diathesis alternation（语态交替）：容易生成不自然的被动式命令。
    
- Negation switching（否定切换）：与反极性替换存在重叠。
    
- Ellipsis（省略）：短指令省略成分后容易产生歧义，也与增删操作重叠。
    

### 5. Discourse（话语层面变化）：全部排除

机器人指令在这里被视为直接的祈使句。

改变语气、句式或话语组织方式，可能改变指令的言语行为或指令力度；而过于宏观的话语结构变化，也不利于对单条原子指令进行可控测试。

注意：这不代表所有间接表达都被排除。论文在其他分类中仍保留了一些语用层面的表达，例如请求、疑问式指令和提示等。这里排除的是 EPT 中的 Discourse 类别，不能直接理解为排除所有间接指令。

### 6. Other（其他）：只保留 Addition（增加）

- Addition（增加）：保留，例如在原指令中增加修饰或语境信息，但要求不改变任务含义。
    
- Deletion（删除）：可能删掉必要信息，或者造成语法错误。
    
- Change of order（顺序变化）：在短祈使句中往往不自然。
    
- Semantic-based types（基于语义的类型）：缺乏足够精确的定义，不利于可控评测。
    

### 7. Extremes（极端类型）：全部排除

- Identity（恒等）：没有发生任何改写。
    
- Nonparaphrase（非释义）：不保持原有语义。
    
- Entailment（蕴含）：表示推理或蕴含关系，不等于语义保持的改写。

|改写维度|类型|含义|
|---|---|---|
|物体词汇（Obj-Lexical）|Same polarity habitual|习惯性同极性替换|
|物体词汇|Same polarity contextual|语境性同极性替换|
|物体词汇|Addition|增加描述|
|动作词汇（Act-Lexical）|Same polarity habitual|习惯性同极性替换|
|动作词汇|Same polarity contextual|语境性同极性替换|
|动作词汇|Addition|增加描述|
|动作结构（Act-Structural）|Coordination|并列结构变化|
|动作结构|Subordination|从属结构变化|
|动作语用（Act-Pragmatic）|Personal need|个人需求式表达|
|动作语用|Question directive|疑问式指令|
|动作语用|Embedded imperative|嵌入式祈使句|
|动作语用|Permission|请求许可式表达|
|动作语用|Hint|暗示式表达|

这里要注意：表 6 不是简单列出 13 种互不相关的攻击，而是把改写分成物体和动作两个维度，再进一步细分动作的词汇、结构和语用变化。 这让作者能够分别测试物体指称变化、动作表达变化，以及两者组合后的影响。

例如，原始指令是 `Turn on the stove`：

- 物体维度：改写 `stove` 的表达。
    
- 动作维度：改写 `turn on` 的表达，或者增加描述。
    
- 结构维度：调整动作所在句子的并列或从属结构。
    
- 语用维度：将直接命令改成疑问式指令或暗示。
