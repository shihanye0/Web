# REA 安装与使用说明

REA 已以 `rea-agents@6.4.0` 安装，MCP ID 为 `rea`，接入 Codex、Claude Code、Antigravity、DSH。共享 Skill 为 `C:/Users/Lenovo/.skillshub/reverse-engineer-anything`。本次实际验证的是 JavaScript 制品静态分析；原生反编译引擎尚未配置。

## 本机配置

CLI：`C:/Users/Lenovo/AppData/Roaming/npm/rea.cmd`。

四个客户端使用同一个绝对路径启动入口：

```json
{
  "command": "D:/node-v22/node.exe",
  "args": [
    "C:/Users/Lenovo/AppData/Roaming/npm/node_modules/rea-agents/scripts/rea.mjs",
    "mcp"

```

这是服务规格示例；Codex 使用 TOML，DSH 使用 Connector 存储，不能将这段当成四种配置文件的完整内容。各原生路径及 Junction 目录见 [[开源工具多Agent共享配置-2026-10-13]]。`D:/node-v22` 是历史目录名，实际 Node 版本已单独核对，目录名不是版本证据。

本轮 Claude Code 与 Antigravity 用 REA 的原生 `setup` 完成 MCP 注册，并关闭其 Skill 安装，保留共享 Skill 源。已安装的 npm 6.4.0 不支持 DSH setup 客户端参数；DSH 通过本机 Connector 的原生导入逻辑接入。

## 如何使用

新开或重载客户端会话后，可以提出带有确切本地制品路径的任务：

> 使用 REA 静态分析 `E:/项目/应用制品` 的 JavaScript/Electron 模块，列出入口、关键功能与证据位置；区分直接观察、推断和未解决项。

REA 适合分析软件制品、反编译结果和指定运行时证据。普通源码仓库的结构理解，优先继续使用已有代码索引与源码工具。目标路径应是实际目录或 ASAR，不以工具返回推断没有验证过的功能。

终端示例（PowerShell 7）：

```powershell
$rea = 'C:/Users/Lenovo/AppData/Roaming/npm/rea.cmd'
& $rea --version
& $rea doctor --help
& $rea analyze-javascript-application --help
# 将下面路径替换为实际应用目录或 ASAR
& $rea analyze-javascript-application 'E:/项目/应用制品' --format json
```

`analyze-javascript-application` 的参数与本轮安装版本的实际帮助输出一致。大型应用应按资源状况设定分析超时/堆上限，不把超时产生的部分证据写成完整结论。

原生客户端检查：

```powershell
claude mcp get rea
codex mcp get rea --json
agy mcp list
```

工具枚举与健康检查只能确认接入。正式分析还要执行对应类型的真实调用，并检查输出和证据范围。
