# AI 创作四层复审与专业术语防误伤指南

> 沉淀自 2026-11 研究生课程综述 Word（《软件学报》体例 13 页）与配套 16 页学术汇报 PPT 的多轮双 Agent 交叉复审实战。遵循 `C:\Users\Lenovo\.agent-config\rules\document-authorship.md` 的「三去向分流阀」原则：单项目复盘与可复用方法论沉淀至知识库，确定性模式沉淀至 `--jargon-file` 或零 Prompt 成本校验脚本，不反向膨胀全局规则热路径。

## 一、核心教训：为什么静态扫描 0 命中仍会被看出 AI 味？

1. **盲区在“正文之外”**：既有 `audit_report_voice.py` 只扫描 Word 正文与表格，不覆盖 **PPT 屏幕文字**与 **Matplotlib/SVG 插图源码**。结果 Word 正文已经干净，PPT 封面/目录/总结仍残留内部交付验收腔（如 `综述核验画像`、`本地 PDF 与出版元数据交叉核验`、`顺序引用率 100%`、`证据边界声明`），图 3 仍残留 `摒弃`、`首偏阶段`、`形式化门禁`。
2. **术语治理不能一刀切**：AI 写作里最隐蔽的问题不是“用了专业词”，而是**把原论文已有术语译偏、译乱，或用 CI/CD、Agent 工程黑话替代领域常规表达**；同时若不回查原论文英文原文，又极易把原论文确实使用的冷门精准词误杀成“AI 套话”。
3. **图表比正文更容易出现统计口径与因果失真**：把正文里的定量结论压缩进示意图小框时，极易省掉统计分母（例如把“失败样本中 79.5%–95.5% 为规划级失效”压成“79.5%–95.5% 规划偏离”），或顺手用 `→` 箭头串联其实只是并列枚举的现象（暗示固定先后发生顺序）。
4. **长句堆叠与旧式机械收据**：AI 起草综述时容易用分号把多篇论文的“背景—方法—数据—评述”硬压成 200–300 字单句；半角期刊体例下若分句脚本未启用 `--punct-style auto`，还会漏报真实句长。

## 二、可复用方法：专业术语三分类法（防误伤 + 抓错译）

审查任何中文学术报告、综述或汇报 PPT 时，先将待查术语对照**原论文英文原文 / 权威教材**分为三类处理：

| 分类 | 判别标准 | 本次典型案例 | 处理动作 |
| --- | --- | --- | --- |
| **一、原论文真术语** | 英文原论文标题、摘要或方法节有精确对应词，且中文译法符合学科习惯 | `去噪速度场` (*denoising velocity field*)、`排斥性 InfoNCE` (*repulsive InfoNCE*)、`贴片注意力支配` (*Patch Attention Dominance*)、`表观高性能` (*apparent competence*)、`将轨迹坍缩为粗粒度数值` (*collapse... into coarse scores*)、`首个被攻破的信任边界` (*first-compromised-trust-boundary*)、ERT 原题语境下的 `审计` (*Auditing*) | **坚决保留，不误伤** |
| **二、AI 错译 / 概念漂移 / 一词两译** | 原论文有明确概念，但 AI 机翻直译、缩写引发物理概念混淆，或同段前后译法打架 | `oracle phrase search` 误译为 **`神谕短语搜索`**（应为 `Oracle 短语搜索`）；操控任务的 `critical stage/phase` 误译为 **`关键脆弱相位`**（中文工科“相位”指波/周期相角，应为 `阶段`）；`action-sequence length +55%` 压缩成 **`步长 +55%`**（混淆控制步长 step size 与动作步数）；同段把 *grounding* 译 `接地` 却把 *Grounded* 译商业词 `落地`；*Harness* 误包装成 `执行底座`（应为 `执行框架`）；*world-bound* 机翻为 `世界绑定` | **对照原文逐一纠偏**，中英文摘要同步检查（如英文 `gates` 同步改 `checks`） |
| **三、非原论文的 AI/Agent 黑话与审计腔** | 原论文中根本不存在，纯属把软件工程/Agent 治理词或内部验收收据搬进学术正文 | `门禁 / 双门禁`（来自 CI/CD quality gate，改 `可执行性检查 / 双重校验`）；自拟模块叫 `XX 引擎`（保留 `物理引擎`，自拟模块改 `模块 / 方法`）；`防线失配 / 击穿 / 摒弃 / 架构跃迁 / 立体化体系`；PPT 出现 `核验画像 / 本地 PDF 交叉核验 / 顺序引用率 100% / 证据边界声明`；硬缩词 `首偏阶段` | **全四层清零**，恢复自然学术表达 |

## 三、交付前四层联审清单（Word + 表格 + 矢量图 + PPT）

每次“文档 + 配套汇报 PPT”联合交付前，按以下顺序执行一次闭环核查：

1. **四层同词扫描**：用短 Python 脚本一次性提取 **Word 正文、Word 表格单元格、Matplotlib/SVG 源码文本、PPT 全部页面文本与原生图表 XML**，统一检索 `--jargon-file` 与高风险词表，杜绝“正文改了、图 3 和 PPT 没改”。
2. **中英互验**：若文档含中英文摘要或双语术语括注，同步检查英文是否残留中文黑话的直译（如 `kinematic and visibility gates` → `checks`），以及英文摘要词数是否遵守教师/期刊上限（如 ≤200 词）。
3. **图表二问核验（防误导读者）**：
   - **分母问**：图内每个百分比是否写清或紧邻写明统计分母？（例如“各模型失败样本中 79.5%–95.5% 为规划级失效”，不能裸写“79.5%–95.5% 规划偏离”）。
   - **箭头问**：图内每条 `→` 箭头是否确实代表时序/数据流/因果关系？若只是多种失效表现并列举例，改为顿号或分栏列举，禁止滥用箭头。
4. **单句压迫度与可读性检查**：运行 `audit_report_voice.py --punct-style auto --jargon-file <project.json>` 后，再抽检超过 200 字的分号串联长句，在自然语意边界改句号断句；同时确认总页数与关键图表落页未被破坏。
5. **汇报状态声明克制原则**：区分“已完成实证”与“拟开展方案”是必须的，但只需在对应章节开篇与总结页末尾各用一句自然平实的说明交代即可，**严禁在封面、目录、表注、尾页多处贴“证据边界声明 / 核验画像 / 尚待实验验证”质检条**。
6. **压缩守恒与打包哈希锁（防泛化偏差与版本错配）**：
   - **压缩先删修饰、保住判断条件**：正文→表格→示意图→PPT→口播压缩时，优先删掉 `画像`、`体系突破`、`立体化` 等低信息修饰，把空间让给**统计分母、比较条件、计划/实测状态与因果强度**，避免科学摘要中常见的“模型自动省掉限定条件、扩大结论适用范围”问题。
   - **交付前单次全量哈希锁**：多文件联合交付（Word + PPT + ZIP）时，必须在所有导出全部结束后再跑一次逐字节哈希校验，确认 `独立 DOCX == ZIP/DOCX`、`独立 PPTX == ZIP/PPTX`、共用插图 `Word PNG == PPT PNG`，杜绝中间态被提前打包或被另一端交叉复审扫到旧快照。

## 四、双向项目词表范式（Vale Accept + Reject 思路）

单纯维护“禁词表”容易在去 AI 味时误杀专业词，或把同一概念改出多个译名。建议每个中大型写作项目维护**一对互补文件**：

1. **只含 `Reject` 正则的筛查表**（直接兼容 `audit_report_voice.py --jargon-file`）：
   - 范例：`E:\论文\2026_VLA综述结课作业\paper-context\workflow\vla-jargon-audit.json`
   - 仅收录本项目确认的机翻错词、工程黑话与 PPT 审计收据泄露；**不把普通高价值词（如“显著”“有效”）写进全局禁词**。
2. **含 `Accept` 白名单与回归正反例的项目术语表**（供写作、润色与复审参考，不直接传入 `--jargon-file`）：
   - 范例：`E:\论文\2026_VLA综述结课作业\paper-context\workflow\vla-term-glossary.json`
   - 每条术语标明四类来源之一：**论文原名**（`paper_original`）、**领域通用术语**（`domain_standard`）、**限定语境术语**（`paper_scoped`，如仅 ERT `[23]` 语境用 `审计`）、**自拟概念**；锁定全篇统一译名，禁止润色阶段做无意义同义替换。

调用命令示例：
```powershell
python -X utf8 C:\Users\Lenovo\.skillshub\chinese-thesis-workbench\scripts\audit_report_voice.py `
  --docx <deliverable.docx> `
  --contract <writing-contract.json> `
  --jargon-file E:\论文\2026_VLA综述结课作业\paper-context\workflow\vla-jargon-audit.json `
  --punct-style auto `
  --output <voice_scan.json>
```

## 五、真实正反对照样例库（Golden Few-Shot / Regression Cases）

相较于不断拉长抽象规则，**少量带原文、改法与理由的正反例**对约束润色与复审更有效：

| 类型 | 样例（改前 / 待审） | 裁决与改后 | 关键判断依据 |
| --- | --- | --- | --- |
| **正例：必须保留** | `Tex3D 在 LIBERO-Spatial 上将 OpenVLA 失效率由 15.6% 推高至 95.8%，显著提高任务失效率。` | **保留原文** | 紧邻具体基准、模型与实测数值，“显著”有据可依，不得因词表机械判错 |
| **正例：必须保留** | `质量多样性 (QD)`、`DTW`、`Grounded Semantic Re-Binding`、`去噪速度场` | **保留原名** | 原论文或领域标准术语，首次出现给出定义或中文释义后全篇固定名称 |
| **反例：图表漏分母** | `79.5%–95.5% 规划偏离 [9]`（旧版图 2） | 改为 **`失败样本中 79.5%–95.5% 为规划级失效 [9]`** | 省掉统计分母会让读者误解为全部试验的失败率 |
| **反例：假顺序箭头** | `无目标失败 → 时长膨胀 → 定向偏移 → 碰撞违规`（旧版图 2） | 改为 **`无目标失败、步数延长；定向偏移、碰撞违规等`** | 并列表现误用 `→` 会暗示固定先后演化链 |
| **反例：AI 机翻错术语** | `神谕短语搜索` / `关键脆弱相位(critical phase)` / `步长 +55%` | 改为 **`Oracle 短语搜索` / `关键脆弱阶段(critical stage)` / `动作步数 +55%`** | 分别纠正神话词直译、波动相位与任务阶段混淆、step size 与动作步数混淆 |
| **反例：PPT 审计腔** | `38 篇核验英文文献画像；全部 38 篇经本地 PDF 与出版元数据交叉核验，正文顺序引用率 100%。` | 改为 **`38 篇英文文献范围与分布；共梳理 38 篇英文文献（含 3 篇综述），2024–2026 年文献占比 97.4%，按主题对比。`** | 内部写作合同和验收日志不得泄露到对外汇报正文 |
| **反例：硬缩短标签** | `黑盒 QD 过程反馈`（若用于正文或口播） | 正文/口播展开为 **`用执行反馈引导黑盒质量多样性搜索`**（窄表单元格可视空间保留紧凑词） | 按载体区分密度：窄表允许紧凑，正文与讲稿必须自然完整 |

## 六、外部调研依据与规则演进边界（防二次膨胀）

结合 2026-11 跨来源调研，本方法吸收了四类可迁移经验，并明确保持本地规则克制：

- **同一概念同一译名 & 回查权威原文**：参考 Google Technical Writing、中文技术写作规范与 Vale Vocabularies 的项目词表设计。
- **少量正反例评估优于堆砌禁词**：参考 OpenAI / Anthropic 提示与评估指南，以及 ACL 2025（AI 惯用词频率随时间漂移）与 EMNLP 2026（文体效应强于来源效应）的实证结论——**不再向 `audit_report_voice.py` 盲目追加通用学术禁词**，只用项目级 `--jargon-file` + 人工语义复核。
- **警惕压缩阶段的泛化偏差**：参考 4,900 份科学摘要研究（LLM 摘要常自动省掉限定条件、扩大适用范围），将“保留分母、条件与计划/实测边界”列为图表与 PPT 缩写红线。
- **本地共享配置保持稳态**：现有 `document-authorship.md`、`humanizer-cn`、`chinese-thesis-workbench`、`document-reviewer` 与 `ppt_local_lint.py` 能力已完备；仅在未来确有跨项目高频需求时，再考虑向 `ppt_local_lint.py` 增加零误报的 `audit_receipt_leak` 警告，不反向膨胀全局 Prompt 规则。
