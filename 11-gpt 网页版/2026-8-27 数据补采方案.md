我会把补采设计成这几类：

1. **正常前方留空隙**：保持已有成功分布，正常 approach→close，防止新数据把原来的能力冲掉。
2. **杯子刚接触手指/掌缘**：起始时已经很近，示教应该是少量微调后马上闭手。
3. **杯子已经进入手心**：这是最关键的 failure recovery。开局就类似你失败日志里的状态，示教不要继续往前推，而是直接/快速闭手并稳定。
4. **轻微错位的掌心状态**：偏左、偏右、轻微倾斜、深浅不同，示教“微调→闭手”，否则模型可能只记住一个精确摆位。

可以。那就把它做成一套**专门针对 grasp-transition recovery 的补采方案**，而不是泛泛“多采一些抓取数据”。

下面我把你要的三部分都给出来：**采集姿态清单、各类数据比例、每类具体示教动作流程**。同时把哪些是当前日志直接支持的、哪些是我基于现象给出的采集设计建议区分开。

你现在要补的核心不是“杯子在什么地方”，而是让模型稳定学会：

> **当药瓶已经进入抓取邻域，甚至已经在掌心里时，不要继续向前推，而要进入 close → stabilize → lift。**

当前失败场里，模型可以持续 approach，但完整 chunk 长时间 `n_close=0`；而成功场里又确实能自然产生明显 close。因此目前更像是**grasp-transition basin 太窄**，不是完全没有 grasp skill。成功场中 raw policy 曾出现 `Rfinger_max=1.121, n_close=35` 并最终抓住。

---

# 一、采集姿态清单

建议把初始状态分成 **5 个主类**。不要只采“杯子在掌心”这一种，否则可能把正常 approach 能力训练坏。

## A0：标准正常起始——保留原能力

这是原本正常抓取的数据。

药瓶：

- 位于右手前方；
    
- 与掌心还有明显空隙；
    
- 不碰指尖；
    
- 不碰掌心；
    
- 竖直为主；
    
- 位置接近你们现有成功 episode。
    

目的：

> 保留 `approach → close → lift` 的标准轨迹。

这一类不是为了修 bug，而是为了**防止补 recovery 数据后模型过早闭手**。

建议至少覆盖：

```text
中心位
稍左
稍右
稍近
稍远
轻微顺时针
轻微逆时针
```

---

# A1：Near-contact——即将接触

药瓶已经非常靠近手：

- 与指尖/掌心只剩很小距离；
    
- 但还没有明显物理接触；
    
- 手仍是 open/pregrasp。
    

这是一个非常重要的中间层。

期望示教：

```text
极少量 approach
→ 开始 close
→ stabilize
→ lift
```

这里要刻意减少“继续向前冲”的长度。

否则数据还是会强化：

> 靠近了以后继续伸手。

---

# A2：First-contact——刚发生接触

这是第一批真正针对当前问题的数据。

例如：

- 药瓶刚碰到食指内侧；
    
- 刚碰到中指；
    
- 刚碰到掌缘；
    
- 刚碰到拇指与四指之间的入口。
    

此时手仍然张开。

目标行为应该非常明确：

```text
停止明显前推
→ 小幅校正
→ close
→ stabilize
→ lift
```

特别注意：

**不要在示教里把瓶子继续往掌心深处推很多。**

因为你现在恰恰是在纠正：

```text
contact
→ keep pushing
```

要让它变成：

```text
contact
→ close
```

---

# A3：Palm-in——瓶子已经进入掌心

这是现在最关键的一类。

要故意复现失败场：

- 药瓶已经位于拇指和其他手指之间；
    
- 瓶体明显进入掌心区域；
    
- 手指仍然是张开的；
    
- 腕和肘已经接近抓取位置。
    

也就是你最近实机经常出现的那种：

> “都已经在手里了，它怎么还不抓？”

这类数据的动作应该尽可能干净：

```text
开场
→ 几乎不再向前
→ 立即开始 close
→ 指尖包住瓶子
→ 稳握短暂停顿
→ lift
```

如果确实需要微调，可以有一点：

```text
微小 lateral / wrist correction
→ close
```

但不要：

```text
再向前 10~20 帧
→ 再 close
```

否则训练信号又被模糊掉。

---

# A4：Palm-in + 偏差恢复

这是决定以后能不能真正“去概率感”的数据。

不能只采一个完美掌心位置。

要系统扰动：

### 深浅

```text
浅入掌心
标准
稍深
```

### 左右

```text
偏拇指侧
居中
偏食指/中指侧
```

### 朝向

```text
直立
向前倾少量
向后倾少量
顺时针少量
逆时针少量
```

### 高度

```text
略高
标准
略低
```

目标不一定都是“立即闭手”。

正确示教可以是：

```text
状态已经可抓
→ close
```

或者：

```text
状态略偏
→ 2~5 帧小修正
→ close
```

但核心是不允许演变成新的长距离 approach。

---

# 二、数据比例

这部分是**采集设计建议，不是现有文件里已有的固定比例**。

如果现在主要目标是修复 grasp transition，同时尽量不损伤原有正常抓取能力，我第一轮会用：

|类别|比例|
|---|--:|
|A0 标准正常起始|30%|
|A1 near-contact|15%|
|A2 first-contact|20%|
|A3 palm-in|25%|
|A4 palm-in 偏差恢复|10%|

也就是：

```text
30 : 15 : 20 : 25 : 10
```

为什么不是掌心数据占 70%？

因为如果 recovery 数据过重，很容易学出一个新问题：

> 一看到瓶子比较近就提前 close。

这样正常 approach 会退化。

所以第一轮我希望 recovery 总体占 **55%**：

```text
A2 + A3 + A4 = 55%
```

正常/近接触仍保留 **45%**：

```text
A0 + A1 = 45%
```

这是一个比较平衡的起点。

---

## 如果第一轮训练后仍然掌心不闭

第二轮可以提高：

```text
A0 25%
A1 10%
A2 20%
A3 30%
A4 15%
```

即 recovery 提到 **65%**。

但我不建议一开始就这么重。

---

# 三、采多少条

如果你们现在预算有限，我宁愿：

> **多姿态、短 transition、重复少一点**

也不要：

> 少姿态、每个录很多完整长 episode。

例如第一轮最低可用规模，我建议大约：

```text
100~150 条 grasp-focused episode/clip
```

可以拆成：

```text
A0   30~45
A1   15~25
A2   20~30
A3   25~40
A4   10~20
```

如果采集资源够，我更希望做到：

```text
200~300 条
```

但关键不是绝对数量，而是**初始状态覆盖**。

对这种局部 transition bug：

> 30 个不同掌心状态

通常比：

> 一个状态重复 100 次

更有价值。

---

# 四、每类具体示教动作流程

这里是最重要的一部分。

## A0 标准正常起始

示教：

```text
1. open/pregrasp
2. 稳定 approach
3. 接近瓶体
4. 在还没把瓶子顶进掌心之前开始 close
5. 手指持续闭合
6. 稳握 0.3~0.8s
7. lift
8. 后续可以继续倒药，也可以结束 grasp clip
```

关键：

**不要让 close 出现在“已经顶到底以后”。**

模型需要学到 close 与 approach 有重叠，而不是严格：

```text
approach结束
→ 停
→ close
```

---

# A1 Near-contact

示教：

```text
1. 起始已经很近
2. 只做很短 approach
3. 很快启动 close
4. approach速度明显降低
5. fingers继续收紧
6. stabilize
7. lift
```

你希望模型学到：

> 距离已经很近时，下一步不是重新跑一遍完整 approach。

---

# A2 First-contact

示教：

```text
1. 起始时瓶子刚接触指/掌
2. 几乎停止 forward motion
3. 必要时极小 wrist/elbow correction
4. 立刻 close
5. 持续 close 到稳定抓握
6. hold
7. lift
```

这一类一定要强调：

```text
forward velocity ↓
finger close ↑
```

这个负相关关系很重要。

也就是说：

> 越进入接触，越不应该继续伸；越应该闭手。

---

# A3 Palm-in

这是最应该统一示教风格的一类。

推荐：

```text
t0:
瓶子已经在掌心
手开着

t0 ~ very short:
保持 arm 基本稳定

随后：
finger close 快速而平滑增加

close建立：
小量 wrist/arm compliance即可

稳定：
hold

然后：
lift
```

理想上，这类 transition 在视觉上非常容易理解：

```text
瓶子不再继续向掌心深处移动
但手指明显收拢
```

这正好和当前失败轨迹形成反例。

---

# A4 Palm-in 偏差恢复

这里不要强求所有状态“原地闭手”。

正确示教应该因状态而异。

如果位置已经可抓：

```text
close
→ stabilize
```

如果略偏：

```text
微调 2~10 帧
→ close开始
→ 修正和close可以部分重叠
→ stabilize
```

最好不要做：

```text
大幅撤回
→ 回到标准起点
→ 重新完整approach
```

因为那会教模型：

> 掌心失败态需要 reset。

而你现在恰恰想消灭这种行为。

---

# 五、非常重要：close transition 要怎么录才“明显”

建议采集时专门检查 hand action 曲线。

不要只靠人眼觉得“这条抓得不错”。

你真正需要的是 finger action 在 transition 周围具有清晰结构：

```text
前段：
Rfinger低

接近 contact：
开始明显上升

抓取：
快速跨过当前 natural close 区

稳定：
维持高值
```

你现在 live 判定里 natural close 是用 `Rfinger_max > 0.55` 来观察。现有成功场也确实出现过明显超过这个量级的 policy close。

所以补采后可以离线检查每条 demo：

```text
有没有明确的 low → high finger transition
```

如果一条数据从第一帧开始手就已经闭得差不多了，它对修当前问题价值很低。

---

# 六、不要只采完整倒药 episode

这一点我比较强烈建议。

目前至少有两个相对独立的问题：

```text
grasp transition
grasp → pour transition
```

你刚刚已经看到一场是：

> 自然抓取成功，但是一直没有倒药。

因此如果现在每次都要求采：

```text
抓
→ 抬
→ 找橙杯
→ 倒
→ 放回
```

采集效率会很低，而且会把两个问题耦在一起。

更好的数据组织是：

### Grasp-recovery clips

重点：

```text
起始状态
→ grasp
→ lift一点
```

结束。

### Full-task episodes

另外保留一部分：

```text
正常抓取
→ 抬起
→ target cup
→ pour
```

这样才能既修局部 skill，又不破坏长时序任务。

---

# 七、我建议 grasp 数据与完整任务数据的比例

如果这次训练目标主要是修抓取，我会让新增加的数据里：

```text
约 70% = grasp-focused / recovery clips
约 30% = full pour episodes
```

这是训练设计建议，不是已有实验结论。

这 30% full task 很重要，因为如果全部只采抓住就结束，模型可能加强 grasp，却削弱：

```text
grasp → lift → pour
```

而你们现在本来就已经有 no-pour 问题。

所以不能完全不采完整任务。

---

# 八、倒药 transition 也顺手补一点

既然已经上机采数据，我其实建议把 `grasp → pour` 也一起增强，但数据标签/分组要分开。

尤其采：

```text
刚抓稳
→ 明确抬起
→ 向橙色杯靠近
→ 建立对准
→ 腕开始翻转
→ pour
```

因为最近成功抓取那场里，抓住后连续 raw chunks 都没有真正产生 pour target，最后触发 no-pour terminal。

所以这次补采最好不要只救第一关，然后下一轮又卡第二关。

---

# 九、采集现场可以直接用的摆位矩阵

如果要做到可复现，我建议现场做一个简单 grid。

比如以 nominal bottle position 为中心：

```text
X:
-3cm
0
+3cm

Y:
near
nominal
far
```

再叠加接触类别：

```text
free-space
near-contact
first-contact
palm-in
```

当然不是所有组合都要完整笛卡尔积。

但至少要让采集不是：

> 人随手放一个觉得差不多的位置。

而是：

> 我们知道这一条属于哪一种初始 basin。

如果实际杯子尺寸比较小，3 cm 可以缩成 1~2 cm；具体数值最好以你们成功/失败图里的真实差异为基准。

# 十、建议每条 episode 都保存的 metadata

这一点以后分析会非常省事。

至少记录：

```text
initial_class:
    A0/A1/A2/A3/A4

offset_x:
offset_y:
orientation_bucket:

contact_at_start:
    none / near / finger / palm

expected_recovery:
    direct_close / micro_adjust_close

full_task:
    true/false
```

如果人工觉得麻烦，哪怕最少只记录：

```text
A0
A1
A2
A3
A4
```

都比以后完全靠看视频猜强得多。

# 十一、质量验收：哪些数据应该丢掉

以下 episode 不要因为“最后成功抓了”就保留。

### 1. 长时间顶瓶后才抓

```text
push push push push
→ close
```

这正是在强化 bug。

### 2. 开场就是已经闭手

缺乏：

```text
open → close
```

transition。

### 3. 人为补救太多

比如瓶子滑走后，人重新扶回去。

视觉和动作因果已经污染。

### 4. reset 后才成功

尤其是：

```text
失败
→ 回起点
→ 第二次成功
```

这种不要拿来教 recovery。

### 5. 抓取过程中遮挡严重

如果人的手一直留在画面内，会形成错误视觉 cue。

---

# 十二、训练后怎么验收，才能证明不是“又靠运气”

千万不要只跑：

> 连续 5 场标准位置成功 4 场。

那证明不了 basin 扩大。

建议固定做一个小型 test matrix：

|测试组|场景|
|---|---|
|T0|标准前方留空|
|T1|非常近但没接触|
|T2|刚接触|
|T3|已进掌心|
|T4|掌心偏左|
|T5|掌心偏右|
|T6|轻微倾斜|

每一组至少若干次。

重点观察不是只有最终成功率，还包括：

```text
first_close_time
first_close Rfinger_max
n_close
forward motion after contact
是否触发 guard
是否 retry
```

真正理想的新 checkpoint 应该表现为：

```text
T0:
正常 approach → close

T1:
较早 close

T2:
停止继续顶 → close

T3:
几乎直接 close

T4/T5/T6:
微调 → close
```

而不是：

> 标准位置更容易抓了，但掌心状态还是死。

---

# 十三、对现在 A 方案的配合方式

补采和 A 不是二选一。

A 控制层负责：

```text
不重复 reset
不在 no-close 时无限 DIP 推
不替模型闭手
```

数据/训练负责：

```text
扩大 natural-close basin
```

最终你希望达到：

```text
过去：
初态稍有变化
→ 可能进入 no-close basin

训练后：
这些状态
→ 都落到 close basin
```

这才真正接近你说的：

> **“不要抓或者不抓靠概率。”**

更准确地说，是让不同合理初态都映射到正确的抓取行为，而不是要求完全相同的初态靠随机性碰结果。

如果马上开采，我建议先从 **A3 掌心直闭、A2 刚接触闭手、A0 标准正常抓** 这三类开始，它们信息价值最高。你想先按 **100条小批次**、**200条标准批次**，还是 **300条完整批次** 来规划？
