# LIBERO-Para：面向 VLA 模型释义鲁棒性的诊断基准与指标

> [!abstract] 一句话结论
> 论文把机器人指令的释义变化拆成 **Action × Object** 两个可控轴，构造了 4,092 条、43 个变化单元格的 LIBERO-Para，并用 PRIDE 和轨迹诊断证明：VLA 模型在见过任务、只改变指令表达时仍会明显失效，主要瓶颈偏向物体词 grounding，且约 79.5%–95.5% 的失败属于从一开始就偏离正确任务的 planning-level failure，而不只是动作执行误差。

## 1. 研究问题

### 1.1 论文要回答什么

- **研究对象**：经过有限环境数据 fine-tuning 的 Vision-Language-Action（VLA）模型。
- **核心问题**：模型在 canonical instruction 上表现很好，但仅仅把测试指令改写为语义保持的 paraphrase 后，是否仍能识别同一个机器人任务？
- **进一步问题**：性能下降来自哪种语言变化？是 action 表达、object reference、两者交互，还是实际控制阶段的误差？
- **评测要求**：固定场景、任务和动作目标，只改变指令语言；所有 paraphrase 在测试时 held out，避免把“新任务”与“新表达”混在一起。

### 1.2 现有方法哪里不足

- 传统 LIBERO 主要用固定指令评估视觉/场景泛化，对语言表达变化覆盖不足。
- CALVIN、LADEV 等工作能够涉及重述指令，但没有像本文一样对 action 和 object 两个核心语义组件做完整的交叉控制。
- LIBERO-PRO、LIBERO-Plus、LIBERO-X 把语言变化放在更宽泛的 multimodal perturbation 中，语言不是唯一主变量。
- LangGap 更直接研究语言 conditioning，但部分扰动会改变任务语义，例如改变要抓取的对象，因此可能把“语言变化”和“任务变化”混淆。
- 单一 binary Success Rate（SR）把所有 paraphrase 等价处理：简单的“加一个副词”和困难的“替换物体词并改成暗示句”都只得到 0/1，不能表示难度梯度。

### 1.3 论文如何界定自己的增量

1. **基准层**：用两个正交轴控制 action expression 与 object reference，形成 43 个细粒度变化单元格。
2. **指标层**：提出 PRIDE（Paraphrase Robustness Index in Robotic Instructional DEviation），把关键词相似度与依存结构相似度合并，并与成功条件结合。
3. **诊断层**：用成功轨迹构造 pseudo-GT，通过 DTW 将失败分为 Near-GT 和 Far-GT，区分 execution-level 与 planning-level failure。
4. **验证层**：在 7 个 LIBERO VLA 配置及 2 个 CALVIN 原生 VLA 上复核主要发现。

### 1.4 论文不回答什么

- 不证明某一个具体内部模块（例如 cross-attention 或 planner）是唯一因果来源。
- 不证明模型在真实机器人上的表现；实验只在 LIBERO/CALVIN simulator 中进行。
- 不研究 paraphrase augmentation 能否解决问题；作者担心生成数据与测试分布重叠，因此把它留给未来工作。
- 不做 attention 或 intermediate representation probing。
- 不覆盖每种可能的复合语言变化；每个轴一次只使用一种变化类型，组合主要是一个 Object 类型与一个 Action 类型。

## 2. 核心概念与术语

| 概念 | 本文含义 | 与相近概念的区别 | 对我的研究的意义 |
|---|---|---|---|
| Paraphrase robustness | 指令换一种表达但任务语义、场景和目标不变时，VLA 仍能完成任务的能力 | 不是新任务泛化，也不是视觉 OOD；关键是 language form 改变 | 可作为语义保持 instruction attack 的核心威胁模型 |
| Action axis | 改写动作如何被表达，包括 lexical、structural、pragmatic 三类 | 不改变目标物体；不等于改变动作本身 | 用于测试 action instruction 的显式程度和句法负担 |
| Object axis | 改写目标物体的名词 reference，采用 addition 与两种 same-polarity substitution | 不增加颜色、位置等视觉属性；不改变真实目标 | 直接测试语言到视觉对象 grounding 的鲁棒性 |
| Compositional variation | 同时改变 Object 与 Action，形成 3 × 10 个交叉单元格 | 不是把两次独立实验简单相加；交互效应正是论文要测的对象 | 提醒后续攻击实验不能只做单轴 ablation |
| `S_K` | content words 的最大余弦匹配平均值 | 是方向性的 O→P 匹配，不是严格对称距离 | 衡量 action/object 关键词保留程度 |
| `S_T` | 依存树的归一化 TED 反映结构保持程度 | 依存边标签用 POS/dep relation，减少词面替换对结构分数的直接影响 | 衡量从 imperative 形式偏离了多少 |
| `PD` | `1 - [αS_K + (1-α)S_T]`，表示语言偏离程度 | 只描述 paraphrase 难度，不代表模型一定失败 | 可作为攻击样本难度轴 |
| PRIDE | 成功样本取 `PD`，失败样本记为 `0` | 不是纯文本相似度，也不是独立的语义真值分数 | 同时编码“样本有多难”和“模型是否成功” |
| Near-GT | 失败轨迹仍接近该任务成功轨迹 | 只能近似 execution-level failure | 可把语言误解与控制失误初步分开 |
| Far-GT | 失败轨迹远离成功轨迹 | 更像 planning/task identification 偏离，但不是内部 planner 的因果证明 | 诊断 instruction-to-task mapping 是否断裂 |

## 3. 论文贡献

1. **控制型 benchmark**：在 LIBERO-Goal 上建立 `3 Object types × 10 Action types` 的双轴设计，共 43 个单元格、4,092 条 paraphrase 指令。
2. **任务相关指标 PRIDE**：把 semantic keyword preservation 与 syntactic restructuring 拆开，再按成功与否给出 success-conditioned robustness score。
3. **跨模型发现**：7 个 VLA 配置在 paraphrase 下均明显退化，下降 `22.8–51.9 pp`；物体词变化通常比动作表面重写更危险。
4. **失败机制诊断**：用 EEF 位置轨迹、DTW 和 pseudo-GT 显示，大多数失败从任务轨迹规划阶段就已偏离。
5. **跨基准复核**：构造 CALVIN-Para，在不同 simulator、任务和 VLA 架构上复现三条主要发现。

> [!note] 贡献类型判断
> 这不是只提出一个新数据集。它的完整增量是“控制变量设计 + 任务相关距离指标 + 轨迹级故障分解 + 跨基准验证”。如果只记住“LIBERO-Para 是一个数据集”，会漏掉论文最有价值的诊断框架。

## 4. 方法主线

```text
LIBERO-Goal canonical instructions
        ↓
Object / Action 轴向生成 paraphrase
        ↓
LLM verifier 过滤语义与语法 → axis-wise merging → final verification
        ↓
43 个 variation cells，全部 paraphrase 只在测试使用
        ↓
7 个 VLA × 5 seeds 评测 SR
        ↓
PRIDE 分解语言难度；DTW 分解 Near-GT / Far-GT
        ↓
物体 grounding 是主要瓶颈，失败以 planning-level divergence 为主
```

### 4.1 输入、变量与控制条件

- **输入**：LIBERO-Goal 的 10 条原始操作指令及对应初始场景。
- **被改变的变量**：指令中的 action 表达、object reference，或两者同时改变。
- **被固定的变量**：场景、初始状态、任务目标、真实操作对象、环境成功标准。
- **训练/测试关系**：模型在 canonical LIBERO 指令上 fine-tune；paraphrase 指令仅用于 held-out evaluation。
- **对照组**：`None × None` 原始指令；另外有仅 Action 变化、仅 Object 变化和组合变化。
- **主要混杂因素**：LLM 生成质量、语义保持判定、单一 canonical object name、不同模型 base-task 能力、固定演示路径、simulation 与 real-world 差异。

### 4.2 两轴变化空间

#### Object axis：3 种非空变化

| 类型 | 例子（原始：`Turn on the stove`） | 保持/改变 | 直观难度 |
|---|---|---|---|
| `Addition` | `Turn on the gas stove` | 保留核心名词，增加限定词 | 较低 |
| `SP-contextual` | `Turn on the cooktop` | 用上下文相关的同极性替代表达 | 中高 |
| `SP-habitual` | `Turn on the cooker` | 用习惯性/常见替代表达 | 中高 |

`SP` 是 same-polarity substitution。Object axis 只关注 lexical-level reference，不主动增加颜色、尺寸、位置、方向等视觉属性。

#### Action axis：10 种非空变化

| 类别 | 类型 | 例子 | 主要增加的语言负担 |
|---|---|---|---|
| Lexical | `Addition` | `Carefully turn on the stove` | 增加修饰但保留命令核心 |
| Lexical | `SP-contextual` | `Switch on the stove` | 动词替换 |
| Lexical | `SP-habitual` | `Fire up the stove` | 更习惯化/口语化的表达 |
| Structural | `Coordination` | `Go to the stove and turn it on` | 增加并列动作结构 |
| Structural | `Subordination` | `Turn on the stove so that it becomes hot` | 增加从句与目的/结果关系 |
| Pragmatic | `Need-statement` | `I need the stove turned on` | 从直接命令转为需求陈述 |
| Pragmatic | `Embedded-imperative` | `Could you turn on the stove?` | 礼貌疑问形式中的嵌入命令 |
| Pragmatic | `Permission-directive` | `May I have the stove turned on?` | 许可请求 |
| Pragmatic | `Question-directive` | `Is the stove heating up?` | 通过问题间接表达目标 |
| Pragmatic | `Hint` | `The stove is still off` | 通过情境暗示恢复动作 |

#### 为什么是 43 个单元格

```text
10 个 Action-only（Object = None）
+ 3 个 Object-only（Action = None）
+ 3 × 10 = 30 个 Compositional cells
= 43 个 variation cells

+ 1 个原始对照 = 44 个完整网格单元格
```

每个 variation cell 约 100 条样本，总计 `4,092` 条 paraphrased instructions；原始对照不计入这 4,092 条 paraphrase。组合实验的价值在于检验：

```text
同时改变两个轴的退化 ?= Action-only 退化 + Object-only 退化
```

论文结果显示并不相等，而是存在 super-additive interaction。

### 4.3 数据生成流程

论文 Appendix A.3 的核心流程不是“一次让 LLM 生成所有 paraphrase”，而是角色拆分：

1. **Axis-wise generation**：generator 分别沿 Action 轴（10 类）和 Object 轴（3 类）生成候选。
2. **单轴 verification**：verifier 检查语义保持、语法自然度以及是否只改了指定成分。
3. **Merging**：把通过验证的 action paraphrase 与 object paraphrase 交叉合并，最多形成 `n × m` 个组合。
4. **Final verification**：再次检查合并后是否仍保持任务语义、是否引入额外视觉/空间属性。
5. **人工审阅**：论文说明所有生成 paraphrase 都经过作者人工 review/filter。

默认生成模型是 `Gemini 2.5 Pro`。附录 Figures 22–30 给出 generator、verifier、merger 及各类型 guideline 的 prompt。

#### 生成约束

- 保持单复数一致。
- 不添加颜色、尺寸、形状、材质等视觉属性。
- 不添加位置、方向、空间关系等属性。
- Object task 只改 object noun；Action task 只改 action elements。
- 每行输出一条 paraphrase，不输出解释或替代方案。

这些约束让“语言表达变化”尽量不变成“观察条件变化”，但它们不能替代独立的人类语义验证。

## 5. PRIDE：把“指令有多难”量化

### 5.1 为什么不能只用 SR

普通 success rate 的问题不是它错误，而是它太粗：

- `SR = 1` 只说明这条指令成功，不说明它是简单的词面变化还是高度间接的表达。
- `SR = 0` 只说明失败，不说明模型是在正确轨迹附近执行失败，还是一开始就找错了目标。
- 直接平均所有 paraphrase，会把“模型只会做简单变化”与“模型能处理各种难度”混成一个数字。

PRIDE 的设计目标是让每条样本先有一个与机器人任务相关的语言偏离度，再把这个偏离度与 success 条件结合。

### 5.2 Keyword Similarity：`S_K`

设原始指令的 content-word 集合为 `O = {o₁, ..., oₙ}`，paraphrase 的 content-word 集合为 `P = {p₁, ..., pₘ}`。每个词由 Sentence-BERT 得到 embedding `e(·)`，对原始句中的每个词找 paraphrase 中最相似的词：

$$
S_K(O,P)=\frac{1}{n}\sum_{i=1}^{n}\max_{j\in\{1,...,m\}}
\cos(e(o_i),e(p_j))
$$

- `S_K` 越高：任务关键 content words 越接近。
- `1 - S_K` 越高：关键词层面的 lexical deviation 越大。
- 论文把 function words 排除，重点保留 action/object 等内容词。
- 默认版本是“原始词 → paraphrase 词”的最大匹配平均，不是双向匹配，也不是严格的集合距离。

**关键边界：** `S_K` 更像“词汇保持程度”，不能单独判定两句话是否真正语义等价。一个词可能 embedding 相似但在具体场景中并不指向同一物体；这也是为什么作者仍需要 verifier、人工评估和 task success。

### 5.3 Structural Similarity：`S_T`

对原始指令与 paraphrase 分别构建依存句法树 `T_O`、`T_P`，使用 tree edit distance（TED）计算把一棵树变成另一棵树所需的最小节点/边插入、删除和替换次数。为降低词面替换对结构距离的直接影响：

- 节点标签采用 POS tag，而不是表面词。
- 边标签采用 dependency relation。
- 用两棵树大小之和归一化：

$$
S_T(T_O,T_P)=1-\frac{TED(T_O,T_P)}{|T_O|+|T_P|}
$$

- `S_T` 越高：句法结构越接近。
- `1 - S_T` 越高：结构重组越明显。
- 该归一化天然把 `S_T` 保持在 `[0,1]` 范围内。

### 5.4 Paraphrase Distance 与 PRIDE

$$
PD=1-[\alpha S_K+(1-\alpha)S_T],\quad \alpha\in[0,1]
$$

论文默认 `α = 0.5`，只是一个中性诊断权重，不是为了在验证集上调到最优的训练超参数。

$$
PRIDE=
\begin{cases}
PD, & \text{episode succeeds}\\
0, & \text{episode fails}
\end{cases}
$$

**读法：**

- `PD` 描述这条 paraphrase 的语言偏离程度，所有样本都可以算。
- `PRIDE` 是 success-conditioned robustness score：成功处理越难的 paraphrase，得分越高。
- 失败样本的 `PRIDE = 0` 不是说该样本没有语言难度，而是说模型没有获得“处理该难度的鲁棒性 credit”。
- 因此 PRIDE 与 SR 的关系应理解为“难度加权的成功表现”，不是一个完全独立于 SR 的语义真值标签。

### 5.5 PRIDE 的数值重算

以 Appendix Table 12 的三条例子为例，`α=0.5` 时：

| 原始 → paraphrase | `1-S_K` | `1-S_T` | 手算 `PD = 0.5(1-S_K)+0.5(1-S_T)` | 论文 PRIDE | 解读 |
|---|---:|---:|---:|---:|---|
| `carefully put...` | 0.00 | 0.07 | 0.035 | 0.03 | 只增加轻微 action modifier，难度低 |
| `put the cheese spread...` | 0.27 | 0.43 | 0.350 | 0.35 | object lexical substitution 同时带来结构/词汇变化 |
| `Is the spread supposed...` | 0.60 | 0.53 | 0.565 | 0.56 | object substitution + indirect question，最难 |

论文 Table 12 中三组样本都呈现 `PRIDE` 随 SR 降低而升高的趋势；这比单看 BLEU/BERTScore 更贴近机器人任务难度。

### 5.6 与通用 NLP 指标的比较

| 指标 | 论文观察到的缺陷 | 精读判断 |
|---|---|---|
| `1 - BERTScore` | 数值范围窄，难以区分轻微 addition 与复合困难样本 | 语义 embedding 相似不等于 task-relevant grounding 相似 |
| `1 - BLEU` | 对词面重叠敏感且波动不一致；可能把简单 object substitution 评得比更难的复合形式还远 | 不适合直接作为机器人 paraphrase difficulty |
| `1 - METEOR` | 总体趋势较好，但对仅改变句法的 coordination 不敏感 | 有一定预测力，但缺少 keyword/structure 的诊断分解 |
| PRIDE | `S_K` 看关键词、`S_T` 看结构，并将成功条件纳入 | 更适合这篇论文的任务相关评测，但仍依赖 parser、embedding 和成功标签 |

## 7. 关键结果：从数字读出什么

### 7.1 Table 2：模型并没有因为 base-task 高分而获得语言鲁棒性

| 模型 | LIBERO-Goal SR | LIBERO-Para SR | 绝对下降 |
|---|---:|---:|---:|
| OpenVLA-OFTgoal | 97.9 | 64.7 | 33.2 pp |
| OpenVLA-OFTmixed | 96.1 | 63.7 | 32.4 pp |
| `π0.5` | 97.6 | 71.4 | 26.2 pp |
| `π0.5` expert-only | 78.6 | 39.1 | 39.5 pp |

**FACT：** 七个配置全部下降，范围 `22.8–51.9 pp`。即使 canonical SR 接近 99%，paraphrased SR 仍可能显著下降。

**INFERENCE：** 这说明问题不像是某个单一 architecture 的偶然 bug，更像是 data-scarce fine-tuning 后，语言到任务的映射仍依赖训练中见过的表面词形。

## 8. 结果解释与失败机制

### 8.1 Finding 1：释义脆弱性跨架构、规模和训练策略存在

论文比较了四类架构、约 `0.6B–7.5B` 参数，以及不同的 fine-tuning data scope 和 VLM training strategy。

- OpenVLA-OFTgoal 与 OFTmixed 使用同一架构，但后者 task-level data diversity 增加约 4 倍；两者在 LIBERO-Para 的下降仍接近（`33.2 pp` vs `32.4 pp`）。
- `π0.5` 联合 fine-tuning 的 LIBERO-Goal → LIBERO-Para 为 `97.6 → 71.4`；只训练 action expert 的变体为 `78.6 → 39.1`，没有表现出更好的 paraphrase robustness。
- 7.5B 的 OpenVLA-OFT 在 PRIDE 上可以接近 0.9B 的 X-VLA，说明参数规模本身不是充分条件。

**作者结论：** 释义脆弱性不能仅用架构、规模、task diversity 或 fine-tuning scope 解释，可能来自更深层的语言到任务映射问题。

**我的判断：** 该 finding 的证据强度较高，因为它同时跨多个配置出现；但它仍是跨模型相关性，不是对“训练策略导致脆弱性”的因果实验。不同模型同时改变了 backbone、action module、数据、优化器和 checkpoint 来源。

### 8.2 Finding 2：Object grounding 是主要瓶颈候选

#### 证据一：Object-preserved 与 Object-paraphrased 的差距

- 将 `None/Addition` 视为 object-preserved，将 `SP-contextual/SP-habitual` 视为 object-paraphrased。
- 所有模型都出现明显下降，范围 `19.8–51.0 pp`。
- `OpenVLA-OFTmixed` 使用更多 task data，却仍有约 `48.3 pp` 的对象保持/替换差距，与 Goal-only 版本的约 `51.0 pp` 接近。

#### 证据二：`α` sweep

- `α→1`：PRIDE 更偏向 keyword similarity；所有模型分数总体下降，表示模型在关键词被保留时更容易成功。
- `α→0`：更偏向 structural similarity；PRIDE 整体上升，说明仅句法变化通常比 object keyword replacement 更不破坏性能。
- OpenVLA-OFTgoal 与 OFTmixed 的 PRIDE–`α` 斜率约 `-17.3`、`-18.7`，表现出较强关键词依赖。
- X-VLA 在 `α≥0.9` 时超过 OFTmixed，说明不同模型可能在 keyword robustness 与 structural robustness 之间有不同 profile。

#### 证据三：LIBERO-Goal 的 single-reference 训练习惯

Figure 12 显示，LIBERO-Goal 中 `stove`、`bowl`、`rack` 等对象在指令中基本始终使用同一个 canonical keyword。模型 fine-tune 时没有在对象 reference 上看到 synonym variation；测试时即使只替换为语义相关的 object noun，也可能无法把语言映射回同一个视觉目标。

### 8.3 Finding 3：失败主要发生在 planning/task identification 层

论文不直接读取内部 planner，而是做外部轨迹诊断：

- 成功 episode 的 EEF 轨迹作为参考，构造每个任务的 pseudo-GT。
- 失败轨迹如果仍在成功轨迹附近，标为 `Near-GT`，解释为 execution-level failure。
- 若很早就偏向另一条空间路径，标为 `Far-GT`，解释为 planning-level / task-identification failure。

论文 Figure 8 的直觉是：

```text
成功：   绿色轨迹 → 接近黑色 mean GT
Near-GT：橙色轨迹 → 大体沿正确路线，但末端控制失败
Far-GT： 红色轨迹 → 从早期开始远离 GT，像是选错了目标/任务
```

### 8.4 Algorithm 1：Trajectory-based failure classification

设某个 LIBERO-Goal task index 为 `t`，episode 集合为 `E`，每个 episode 有轨迹 `τᵢ ∈ R^(Tᵢ×3)` 和结果 `sᵢ∈{0,1}`，重采样点数 `K=50`。

```text
1.  S_t ← {e_i ∈ E | s_i = 1}          # successes
2.  F_t ← {e_i ∈ E | s_i = 0}          # failures

3.  对每个成功轨迹：
4.      τ̂_i ← RESAMPLE(τ_i[:, :3], K)
        # 只取 proprioception 的前三维 EEF position (x,y,z)
5.  τ_GT ← mean({τ̂_i | e_i ∈ S_t})     # pseudo ground truth

6.  L_max ← max_{e_j∈S_t} T_j
7.  对每个 episode e_i ∈ E：
8.      τ'_i ← RESAMPLE(τ_i[:L_max, :3], K)
9.      d_i ← DTW(τ'_i, τ_GT)
        # fastdtw，local cost = Euclidean distance

10. τ_t ← max_{e_i∈S_t} d_i
11. 对每个失败 episode e_i ∈ F_t：
12.     若 d_i ≤ τ_t：label(e_i) = Near-GT
13.     否则：          label(e_i) = Far-GT
```

#### 为什么用 DTW

- episode 长度不同：成功可能提前终止，失败可能跑满 maximum step limit。
- 普通 point-wise Euclidean distance 需要固定长度，且不能处理相同空间路线的速度/时间错位。
- DTW 允许时间轴对齐，适合比较“路径形状是否接近”。
- 所有轨迹先线性重采样到 50 个点，减少长度差异对计算的影响。

#### 为什么只取 EEF `(x,y,z)`

原始 proprioceptive state 有 7 维：`(x,y,z,rx,ry,rz,g)`。论文只用前三维，因为它们最直接反映末端是否朝着正确目标物体移动；orientation 和 gripper state 更容易把“执行细节差异”混入“是否选对任务”的判断。

#### 这个算法实际证明了什么

**FACT：** 在论文的阈值设定下，LIBERO-Para 各模型失败中 `79.5%–95.5%` 被判为 Far-GT，Near-GT 通常低于 5%；`π0.5` expert-only 是例外，Near-GT 为 `12.5%`。

**INFERENCE：** 多数失败不像“已经选对目标但控制不准”，更像从初始阶段就没有生成正确任务轨迹。因此提高 paraphrase robustness 的优先方向可能是 instruction-to-task identification，而不是只改 action control。

**不能推出：** Far-GT 不等于“planner 模块因果失败”。它是外部行为标签，也可能包含视觉 grounding、动作头、环境随机性、轨迹多模态等因素。

### 8.5 阈值稳健性与 pseudo-GT 风险

默认阈值是每个 task 成功轨迹距离的最大值，也就是最宽松的 Near-GT boundary。附录 Table 21 进一步使用 success distance 的 `p99/p95/p90` 作为更严格阈值：收紧阈值会把一部分 Near-GT 转为 Far-GT，但 Far-GT 仍然占主导。

**支持点：** 结论不是由单一 `max` 阈值偶然造成的。

**风险点：** LIBERO-Goal 每个任务的训练数据只有一条固定 demonstration path、route diversity 很小；成功轨迹彼此靠近，因此 mean trajectory 适合作为本 benchmark 的 pseudo-GT，但不一定适合多策略、多路径的真实机器人任务。

| 组合变化有超加性 | Table 4 的 `42.6 > 12.9 + 16.4` | 清楚的交互效应证据 |
| 失败主要是 planning-level | DTW/pseudo-GT、阈值 ablation、跨 benchmark | 外部轨迹诊断支持，因果归因仍有限 |
| PRIDE 比通用 NLP 距离更适合此任务 | correlation、qualitative examples、组件消融 | 支持较充分，但依赖 benchmark 与 success label |

### 9.2 容易被过度解读的句子

- “依赖 surface-level matching”是对行为模式的解释，不是论文通过模型内部 probe 直接证明的机制。
- “object grounding 是 bottleneck”是由对象替换导致的性能差距和 `S_K`/`α` 分析支持的主要解释，不等于所有失败都由 grounding 造成。
- “Far-GT = planning failure”是论文的操作性标签定义；更准确地说，是“轨迹在外部行为上偏离 pseudo-GT，符合 planning/task-identification failure 的表现”。
- “PRIDE 是语义距离”不够准确；`PD` 是面向机器人指令的语言偏离度，`PRIDE` 还把 success condition 编码进去了。

> 对这篇论文而言，正文负责讲故事，附录负责提供三个决定可信度的东西：数据是如何被约束和过滤的、指标是否做过稳定性检查、失败分类是否对阈值和模型设置敏感。若只想了解结论可以略读；若要做研究迁移或复现，至少要看 B、C.1、D.2、D.3、E.2。

### 10.1 Appendix A：数据集构造与质量控制

#### A.1/A.2：为什么只选这些 paraphrase 类型

论文从 Extended Paraphrase Typology（EPT）的 26 个 atomic types 和 Directive Types 的 6 类中，按四个条件筛选出 13 类：

1. 适用于 direct robotic manipulation instruction。
2. 保持原始任务含义。
3. 不违反视觉/空间约束。
4. 句法自然。

**保留结构：** Object 3 类 + Action 10 类。

**排除理由摘要：**

| 来源类别 | 处理 | 原因 |
|---|---|---|
| Morphology | 全部排除 | 复数、时态、modal 等可能改变 cardinality、意图或动作解释 |
| Lexicon | 只保留 same-polarity substitution 与 addition | spelling 太轻微；named entity、format change 在此任务中不合适 |
| Lexical-syntactic | 全部排除 | opposite polarity、converse 等容易改变意图或产生不自然命令 |
| Syntax | 保留 coordination、subordination | 其余如 diathesis、negation、ellipsis 要么不自然，要么引入歧义 |
| Discourse | 全部排除 | style/modality 变化可能改变 directive force，且不利于细粒度控制 |
| Other | 只保留 addition | deletion 可能删掉关键成分；order change 在短命令中常不自然 |
| Extremes | 全部排除 | identity 没有变化；non-paraphrase/entailment 不属于语义保持 paraphrase |
| Directive Types | 排除 canonical imperative | 它就是 LIBERO 的原始 baseline，不是新增 Action variation |

**精读意义：** 这部分说明作者不是随意列几个 synonym，而是先从语言学 taxonomy 中做 task-specific projection。与此同时，排除标准也定义了 benchmark 的盲区：它没有覆盖否定、被动、删略、反向关系、复数变化等类型。

#### A.3：数据生成 prompt 的真正作用

附录 Figures 22–30 应重点看“约束是否闭合”，而不只是看 prompt 长什么样：

- generator 负责提出候选，不负责最终判断。
- verifier 检查语义、语法、任务条件和指定轴的修改范围。
- merger 只组合已通过单轴验证的 action/object paraphrases。
- final verifier 再检查组合后是否产生 semantic drift。
- 论文还说明作者手工 review/filter 所有生成结果。

**可迁移经验：** 语义保持攻击数据不应只用一个 LLM prompt 批量生成；至少要有“轴向生成—单轴验证—组合—最终验证”的流水线。

**风险提示：** LLM verifier 不是独立语义真值机。附录 Figure 26 的部分 type-specific 示例中，出现类似 `bowl → cup` 的替换时，需要人工检查是否真的是当前场景中无歧义的同一对象；这应记录为 data-design risk，而不是直接当作论文已证实的错误。

#### A.4：分布统计的解读

- `4,092` 条 paraphrase 来源于 10 条原始 LIBERO-Goal instruction。
- 10 条 instruction 选自 Spatial、Object、Goal、Long 四类任务设置。
- Object axis 3 类；Action axis 10 类；形成 `43` 个 cells。
- Object-only `259` 条，Action-only `870` 条，composition `2,963` 条。
- Object substitution 的 keyword distance `1-S_K` 约为 `0.41–0.45`，而没有 object paraphrase 的行接近 0。
- Coordination/Subordination 的 structural distance `1-S_T` 通常高于 `0.28`；action lexical types 通常低于 `0.17`。

这组统计验证了一个重要设计事实：`S_K` 与 `S_T` 不是随意拼接的两个分数；在作者构造的 cell 中，前者主要由 Object 轴驱动，后者主要由 Action structural 轴驱动。

#### A.5：人工语义验证

| 项目 | 结果 | 应如何理解 |
|---|---:|---|
| 随机抽样 | 205 条，约全量 5% | 不是全数据人工逐条标注 |
| 标注人数 | 15 | 参与者熟悉程度不同 |
| 判断问题 | 是否会在给定场景引发同一 successful behavior | 比抽象句子等价更 task-grounded |
| Gwet `AC1` | 0.854 | 标注者一致性较强 |
| 多数标准 `≥8/15 Yes` | 204/205 = 99.51% | 宽松共识很高 |
| 严格标准 `≥12/15 Yes` | 183/205 = 89.27% | 间接/暗示 speech act 更容易有分歧 |
| 平均 Yes | 14.13/15 = 94.18% | 整体支持语义保持 |

22 条未达到严格标准的样本，分歧主要集中在 suggestive、declarative、indirect speech-act 形式；作者认为更多是对 directive force 的理解不同，而非明显 semantic distortion。

**精读判断：** 人工验证支持数据集整体有效，但 `89.27%` 的严格通过率意味着 pragmatic paraphrase 不是完全无争议的 ground truth。它既是论文设计的困难来源，也是后续攻击实验必须单独报告的标签噪声来源。

### 10.2 Appendix B：PRIDE 的验证与边界

#### B.1 Dependency parser stability

- 使用 `spaCy en_core_web_sm` 获取 dependency tree。
- 随机人工检查 150 个 paraphrase。
- 146/150 解析被判断正确，准确率 `97.3%`。

这支持 `S_T` 在当前短句 benchmark 上可用，但不能推导出 parser 在更长、更多口语化或跨域机器人指令上同样稳定。

#### B.2 TED normalization ablation

| TED 归一化 | Pearson | Spearman | 是否天然 `[0,1]` |
|---|---:|---:|---|
| Sum（当前） | -0.802 | -0.831 | 是 |
| Max raw | -0.715 | -0.747 | 否，有 9 个负值 |
| Max clipped | -0.715 | -0.747 | 需事后 clipping |
| Average | -0.650 | -0.676 | 否 |

`Sum` 归一化同时取得最强的 PRIDE–SR 相关性，并天然保证范围。作者认为 max/average 分母更小，会放大轻微句法差异。

**注意：** 这验证的是在该 benchmark 和该相关性目标下的归一化选择，不等于 sum normalization 在所有语言或所有树结构上都是最优。

#### B.3 与独立 OOD measures 的解耦

| 独立 measure | 与 `PD` | 与 `S_K` | 与 `S_T` | 主要对齐方向 |
|---|---:|---:|---:|---|
| E5 cosine distance（semantic） | 0.844 | 0.784 | 0.378* | `S_K` 更接近 lexical/semantic |
| Content-lemma novelty（lexical） | 0.789 | 0.882 | 0.189^ | `S_K` |
| Dependency-triple Jaccard（lexical） | 0.886 | 0.841 | 0.377* | `S_K` |
| POS-bigram cosine distance（syntactic） | 0.628 | 0.001^ | 0.921 | `S_T` |

`*` 表示较弱显著性，`^` 表示不显著。这个结果支持两个组件分别捕捉 lexical 与 syntactic 维度，而不是同一个分数重复计算。

#### B.4 Table 13/14：相关性该怎么读

- 在 `43 cells × 7 VLAs` 的总体设置中，PRIDE 与 SR 的 Pearson 为 `-0.802`、Spearman 为 `-0.831`。
- PRIDE 在 7 个模型中有 6 个排名第一；唯一例外是 base-task SR 只有 `78.6%` 的 `π0.5 expert-only`，其 base-task noise 可能压过 paraphrase signal。
- 各模型 Pearson 范围为 `-0.671` 到 `-0.877`，均显著（`p < .0001`）。
- 按 cell group 分解后，PRIDE 在 Action-only、Object-only、Compositional 中都领先 `1-METEOR`；composition 中优势最大。

**边界：** PRIDE 与 SR 的负相关是必要的有效性证据，但不是证明 PRIDE 可以预测真实机器人风险的充分条件；两者都在同一个 simulator 和同一套语义有效样本上计算。

### 10.5 Appendix E：CALVIN-Para 的跨基准验证

#### 构造方式

- 15 条 base instructions。
- 每个 variation cell 使用 3 个 paraphrases/每个 base task，共 `43 × 45 = 1,935` 条 paraphrased instructions。
- 排除仅靠颜色区分且难以自然做 object synonym 的任务，以及无法保持 CALVIN 原始 initial-state distribution 的任务。
- 使用 CALVIN 的 `ABCD→D` split：任务在训练分布内，但 paraphrase instruction 在测试时未见。
- 每次把 CALVIN 的 5-step chain 转为 single-task setting，以隔离 paraphrase effect。

#### 结果

| 模型 | CALVIN SR | CALVIN-Para SR | 下降 |
|---|---:|---:|---:|
| RoboFlamingo | 92.3 | 53.1 | 39.2 pp |
| FLOWER | 99.7 | 58.3 | 41.4 pp |

| 模型 | Object preserved SR | Object paraphrased SR | 下降 |
|---|---:|---:|---:|
| RoboFlamingo | 69.8 | 37.2 | 32.6 pp |
| FLOWER | 77.6 | 39.9 | 37.7 pp |

| 模型 | PRIDE | SR 相对 PRIDE 高估 | Far-GT 占失败 |
|---|---:|---:|---:|
| RoboFlamingo | 43.5 | 18.1% | 93.4% |
| FLOWER | 48.3 | 17.2% | 97.1% |

**为什么重要：** RoboFlamingo 与 FLOWER 的 vision-language-action coupling 与 LIBERO 中的 7 个配置不同；在它们上也看到 paraphrase fragility、object bottleneck 和 Far-GT 主导，降低了“只是在 LIBERO 上过拟合”的解释空间。

## 11. 局限、风险与可复现性

### 11.1 作者明确的局限

- 只在 LIBERO simulator 评测，尚未验证真实机器人中的 rendering、physics、sensor noise 是否改变结果。
- 每个轴一次只变一种类型，复合 variation 仍不完整。
- 没有研究 paraphrase-based augmentation。
- 没有做 attention/intermediate representation probing。
- 当前失败机制的 structural hypothesis 留给未来工作验证。

### 11.2 我认为需要额外记录的设计风险

| 风险 | 具体问题 | 对结论的影响 |
|---|---|---|
| 语义标签风险 | LLM verifier 与人工标注都不是绝对真值；pragmatic 样本分歧更高 | SR drop 可能含少量标签/指令歧义 |
| object synonym 风险 | synonym 是否在当前场景中自然、唯一、可被人类理解，不只由词典决定 | “grounding 失败”可能混有表达不自然 |
| 单一 reference 风险 | canonical object name 从训练到测试的分布变化很集中 | 结果更像评估 single-reference overfitting，不代表所有 VLA 语言能力 |
| pseudo-GT 风险 | 固定 demonstration path 让 mean GT 很可靠，但可能低估真实多路径 | Far-GT 的外部有效性有限 |
| 归因风险 | Far-GT 只观察轨迹，不读内部 planner | 不能直接声称某模块因果失败 |
| 统计风险 | 每配置 5 seeds，但主表未报告标准差 | 难判断部分 cell 差异的方差稳定性 |
| 生成分布风险 | 所有 paraphrase 由 LLM 生成并人工过滤 | 可能与普通人类指令分布不同 |

## 12. 这篇论文必须吸收什么

### 12.1 论文做了什么 / 没做什么

| 做了什么 | 没做什么 | 这对研究边界的影响 |
|---|---|---|
| 把 paraphrase 拆成 Object × Action 两轴 | 没覆盖所有语言学变化 | 后续可扩展，但不能声称覆盖“全部语义保持攻击” |
| 固定场景/目标，只换 instruction | 没验证真实机器人 | 适合研究 language-to-task mapping，暂不能直接作真实部署风险估计 |
| 用 `S_K` + `S_T` 构造 PRIDE | 没有独立的语义真值模型 | PRIDE 是任务相关诊断指标，不是通用语义等价判断器 |
| 用 DTW 对失败轨迹分类 | 没读内部 attention/planner | 只能做外部行为诊断，不能直接做模块因果归因 |
| 7 个 LIBERO 配置 + 2 个 CALVIN VLA | 每个 benchmark 的模型数量仍有限 | 跨模型、跨基准趋势可信，但普适性仍需更多架构验证 |
| 公开 generator/verifier/merger prompt | 没研究数据增强训练收益 | 为复现和构造攻击集提供了入口，但防御实验仍是空白 |

### 12.2 对我后续语义保持指令攻击的直接帮助

#### 可以直接继承

1. **双轴分解**：至少把目标实体 reference 与动作表达分开；不能只把整句交给 paraphrase model 后算一个总分。
2. **组合测试**：必须有 Action-only、Object-only 和 Action × Object 三组，才能看 interaction。
3. **生成流水线**：generator、单轴 verifier、merger、final verifier 分工；把“生成质量”和“攻击效果”分开记录。
4. **任务相关难度**：用 `S_K`/`S_T` 或同等可解释指标定义 attack difficulty，避免把所有成功/失败混成一个平均值。
5. **失败轨迹诊断**：如果能得到 action trajectory，应区分“语义识别错误”和“执行控制错误”。
6. **跨模型复核**：至少覆盖不同 VLM backbone、action head、训练策略；只攻击一个模型不能形成一般结论。

#### 不能直接照搬

- 不能直接把 LIBERO-Para 的 object synonym 列表当作所有机器人或所有场景的自然表达。
- 不能把 `Far-GT` 标签直接命名为“planner failure”；应写成 trajectory-level planning/task-identification deviation。
- 不能把 `PRIDE` 当成独立语义判定器；失败样本记 0 的设计与模型 success label 绑定。
- 不能只用 `max successful DTW distance` 做真实机器人阈值；多路径任务需要 path-set、distributional GT 或 task-conditioned representation。
- 不能只复现 43 个 cell 的平均 SR；需要记录每个任务、每类 paraphrase、每个 seed 的分布和不确定性。

### 12.3 可以形成的新问题

- **RQ1：** 在训练阶段加入少量 object paraphrase，能否显著减小 Object-only 和 Compositional 的差距？
- **RQ2：** 显式的 object grounding module 或 canonicalization 是否能改善 `SP-contextual/SP-habitual`，但不损失自然语言覆盖？
- **RQ3：** Action indirectness 与 object synonym 是否存在可预测的 interaction，而不是只在 LIBERO 的 43 个 cell 上出现？
- **RQ4：** 如果使用多条成功 demonstration path，Far-GT/ Near-GT 的结论是否仍然稳定？
- **RQ5：** PRIDE 的 `α` 是否可以由部署环境的语言分布估计，而不是固定 `0.5`？
- **RQ6：** 语义保持攻击是否会造成“模型选择性崩溃”：任务识别错，但视觉控制能力本身仍然可用？

### 12.4 最小验证实验

| 假设 | 最小实验 | 成功标准 | 可能反例 |
|---|---|---|---|
| H1：object lexical variation 是主要瓶颈 | 同一任务、同一模型，配对比较 object-preserved 与 object-paraphrased | Object-only drop 显著大于 action lexical drop | synonym 不自然或任务本身 object ambiguity |
| H2：组合变化具有超加性 | 跑 None、Action-only、Object-only、Composition 四组，按 task/seed bootstrap | `Drop_comp > Drop_act + Drop_obj` 且置信区间不重叠 | 两轴变化并不独立，需改用 interaction model |
| H3：大多数失败是 task identification 偏离 | 记录 EEF trajectory，比较成功 GT 与失败 DTW，并做多阈值敏感性 | Far-GT 在不同阈值和任务上都占主导 | 多路径成功使均值 GT 不适用 |
| H4：PRIDE 比纯文本指标更能预测失败 | 对比 PRIDE、BLEU、BERTScore、METEOR 与 SR 的分层相关性 | PRIDE 在多数模型/分组领先 | benchmark 只覆盖短指令，通用指标未必失效 |
| H5：小量 paraphrase augmentation 有效 | canonical-only、object-only augmentation、full augmentation 三组训练 | object/composition drop 显著下降，canonical SR 不下降 | augmentation 与测试生成器分布重叠 |

## 13. 我的理解与批判

- **最重要的理解**：这篇论文的核心不是“把指令改写后模型会掉点”，而是把掉点分解成可解释的语言轴，并继续追到轨迹层，回答“错在识别还是执行”。
- **最值得迁移的设计**：控制变量比增加 paraphrase 数量更重要；尤其要把 action 与 object 分开，再测组合 interaction。
- **最容易误读的地方**：PRIDE 越高并不直接代表模型越差；它是“成功处理的 paraphrase 难度”，需要结合论文定义读。对失败样本 PRIDE 被置 0，所以平均值越高代表模型在更难样本上仍成功。
- **我仍怀疑的地方**：固定 demonstration path 让 Far-GT 判定很清楚，但也使 pseudo-GT 对真实多路径 manipulation 的代表性不足。
- **对我课题的优先级**：高。它提供了语义保持攻击的生成约束、攻击难度分解、跨模型评测矩阵和失败归因模板；但不能直接照搬其 synonym 或把 simulator 结论外推到真实机器人。

### 13.1 一页纸复述

```text
问题：VLA 是否只记住了 fine-tuning 时见过的指令表面形式？
方法：在固定场景中，把 action 和 object 表达分别/同时改写。
数据：4,092 条 paraphrase，43 个 Object × Action cells。
指标：PRIDE = success-conditioned 的关键词 + 句法偏离度。
结果：全模型下降 22.8–51.9 pp；组合下降 42.6 pp，超过单轴相加。
机制：对象词替换最危险；79.5–95.5% 失败是 Far-GT。
边界：支持行为层的 grounding/planning 脆弱性，不等于内部因果证明。
迁移：双轴攻击、难度分级、轨迹诊断、跨架构验证。
```
