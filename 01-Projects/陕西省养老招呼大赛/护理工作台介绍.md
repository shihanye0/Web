## 一、 系统定位与架构职责

### 1. 为什么需要护理工作台？
在养老照护赛题中，机器人不仅需要在前端与长辈进行“端到端”的语音、视觉与肢体互动，更需要解决**照护闭环与机构协作**问题。如果长辈的情绪低落、呼救、跌倒或口头表达的需求（如“我想喝水”、“帮我叫下李护士”）只留在机器人内存中，就无法形成真正的护理服务链。

护理工作台即为解决此问题而生，是连接 **G1 机器人**、**养老院护士站** 与 **大赛评审专家** 的核心中枢。

### 2. 核心职责边界
* **机器人 G1 侧（前端执行端）**：
  * 主动情绪波动感知（开心/悲伤/生气/平静）；
  * 陪伴多轮对话与表达性肢体交互（挥手致意、双手鼓掌、掌心邀请倾听）；
  * 安全异常监测（疑似跌倒、夜间异常起身、声音求救）；
  * 对话中自动捕获长辈现实照护诉求。
* **护理工作台 Care Console（后端管理中枢）**：
  * 长辈档案与照护偏好管理；
  * 照护需求工单待办追踪（分级排序与护士闭环流转）；
  * 异常安全告警闭环处置（护士接单、记录处置详情、消警归档）；
  * 多轮对话原文回看与通义千问大模型“四要素”会话自动总结；
  * 真实档案与离线测试数据安全隔离，支持多源数据灵活接入。

| 环境          | 访问地址                                                       | 认证方式                              | 数据状态                              | 核心用途                      |
| :---------- | :--------------------------------------------------------- | :-------------------------------- | :-------------------------------- | :------------------------ |
| **云端公网控制台** | [https://82.157.186.52:8443/](https://82.157.186.52:8443/) | 页面登录，账号 `careadmin`，高强度 PBKDF2 密文 | **实时自动同步最新数据**（由本地后台 1~2 秒异步安全上报） | 远程评委展示、手机/iPad 查阅、多终端实时监控 |
| **本机本地控制台** | `http://127.0.0.1:8766`                                    | 局域网/本机直接访问，免登                     | **实时最新**（G1 每次互动后即时更新）            | G1 实机运行调试、现场比赛演示、弱网离线技术保障 |

### 1. 本机工作台启动
在工程根目录运行：
```bash
# 方式 1：前台运行（查看实时访问日志）
python3 -m care_console --port 8766

# 方式 2：后台守护运行（关闭终端不退出）
nohup python3 -m care_console --port 8766 > care_console.log 2>&1 &
```
数据存储于本地 SQLite 生产库：`care_console/runtime/console.db`。

### 2. 云端服务器配置架构
* **服务器 IP**：`82.157.186.52`（腾讯云服务器）
* **接入层**：Nginx 监听 `8443` 端口，强制开启 TLS/HTTPS（Let's Encrypt IP 证书及自动续期），配置 CSP、HSTS、SameSite Cookie 防护及防爆破限流（每分钟 5 次重试限制）。
* **应用层**：systemd 服务 `care-console.service`，监听 `127.0.0.1:8766`，配置 `EnvironmentFile=/etc/care-console/cloud.env`（注入通义千问 API Key 与跨机同步 Token）。
* **数据持久层**：`/var/lib/care-console/console.db`、`/var/lib/care-console/interaction.db`。

## 三、 控制台页面功能与操作手册

工作台左侧导航栏包含 **工作台、老人档案、情绪记录、异常记录、互动记录、系统维护** 六大版块：

```text
┌─────────────────┐
│  伴护·护理工作台  │  --> 导航栏
├─────────────────┤
│ ◫  工作台 (Overview)     --> 指标看板、待跟进异常、照护待办
│ ♧  老人档案 (Elders)      --> 长辈资料、照护备注维护
│ ◡  情绪记录 (Emotion)     --> 识别历史细粒度观测、情绪应对策略
│ !  异常记录 (Anomaly)     --> 跌倒/起身安全事件、护士工单流转
│ ▤  互动记录 (Interaction) --> 陪伴对话原文、AI 四要素总结、互动需求表
│ ⚙  系统维护 (Maintenance) --> 数据源接入配置、交互身份绑定、候选日志发现
└─────────────────┘
```

### 1. 工作台总览页 (`#overview`)
* **四项全局核心指标**：
  * **在册老人**：当前养老机构登记的受护长辈总数；
  * **待跟进异常（红色醒目标记）**：当前处于“待接单、已接单、处理中”的异常告警总数；
  * **情绪事件**：已捕获到的情绪波动并触发应对策略的累计次数；
  * **互动待办**：长辈在日常对话中提出且尚待护士协助办理的现实需求总数。
* **长辈摘要与快捷面板**：
  * 表格列出长辈床位、最近一次情绪识别状态、待跟进异常条数；
  * 点击“查看”可弹出长辈详情卡片，直观展现情绪状态与最近事件；
  * 右侧快捷面板直推“待跟进异常”与“待处理互动需求”，支持一键跳转跟进。

### 2. 老人档案管理 (`#elders`)
* **建档与信息维护**：
  * 支持从交互数据库直接一键关联（自动同步姓名、性别、年龄、床位），保证机器人语音识别与后台档案完全一致；
  * 支持手动建立在册长辈档案（例如首位正式长辈王大爷，男，76 岁，101 房）。
* **照护备注 (Care Notes)**：
  * 护士可在页面上随时记录长辈的生活偏好、基础病史与特殊看护要求（如“降压药需饭后服用，情绪激动时容易心慌，喜欢听秦腔”）；
  * 备注内容永久保存并同步给管理人员。

### 3. 情绪记录与应对策略 (`#emotion`)
* **识别历史（细粒度视觉观测）**：
  * 表格实时记录时间轴、长辈姓名、识别结果（开心、悲伤、生气、平静、无法判断）与推断依据；
  * 区分主线面部识别（`stable_face`）与强肢体线索（点赞、握拳下落、低头捂脸、双手鼓掌、单手挥手）；
  * 支持点击“展开原始 JSON”核验每一帧的置信度、时间戳与特征数据。
* **情绪变化与回应策略**：
  * 记录由情绪波动触发的机器人安抚策略卡片；
  * 明确展示模块建议的**回应目标**（例如长辈悲伤时启动倾听邀请）与**建议语气**（如“温和倾听”、“欢快共情”），并关联到对应的陪伴会话。
* **操作要点**：
  * 为保证长辈高频观测日志阅读时不发生页面卡顿与跳动，**该页面禁用了定时自动轮询刷新**；
  * 查看最新实测数据请点击页面右上角 **↻ 刷新按钮** 或按 **F5**。

### 4. 异常安全监测与护士处置闭环 (`#anomaly`)
* **安全监测事件**：
  * 对接视觉跌倒检测（L3 级疑似跌倒）、夜间体位突变（L2 级夜间快速坐起）、长时间静卧、声音求救等模块。
* **护士闭环处置操作流程（核心演示亮点）**：
  1. 页面红标告警，点击事件右侧的 **“查看”** 按钮弹出处置弹窗；
  2. 弹窗内可核验事件发生时间、详细描述及置信度；若底层提供了音视频录像，可直接在线点播切片证据；
  3. 护士在弹窗下方输入**处置人姓名/工号**（如“李护士”）及**处置说明**（如“已到 101 房扶起老人，检查体温血压正常，老人因找眼镜不慎滑落”）；
  4. 选择流转状态：
     * `已接单 (acknowledged)` → `处理中 (handling)` → `已闭环 (closed)`
     * 如确认属误报，可流转为 `已标记误报 (false_alarm)`；
  5. 提交后系统记录操作审计日志，顶部导航的待处理告警计数相应清减，实现完整的照护闭环。

### 5. 互动记录与 AI 会话总结 (`#interaction`)
* **交流与办理实录**：
  * 汇聚长辈与 G1 的历次陪伴会话；
  * 点击任一会话可展开查看**逐条对话实录**（长辈说的话由 ASR 识别原样展示、机器人的每一句 TTS 回复内容及实际播报回执）。
* **通义千问大模型“四要素”自动总结**：
  * 会话结束后，后台自动调用大模型异步提炼四项核心结论：
    1. **起因**：本次交流触发的背景（如检测到情绪低落或日常问候）；
    2. **诉求（需求）**：严格依据长辈原话提取的客观现实需求，杜绝 AI 凭空臆测；
    3. **过程**：G1 的安抚、陪伴、讲故事、闲聊及防打断处理过程；
    4. **结果**：长辈情绪好转情况与本次陪伴的结束状态。
* **互动需求追踪表**：
  * 汇总长辈在陪伴中明确表达的各项需求（如递送温水、通知护工、协助联系子女）；
  * 标识紧急程度（`urgent > high > normal`）与处理状态，协助护士站统筹安排。

## 四、 系统维护与数据源接入（数据接入机制）

### 1. 为什么默认打开控制台可能看不到以前的测试记录？
* **真实数据与测试隔离**：
  之前开发和调试过程中做过的大量离线测试（悲伤低落、挥拳生气、跌倒模拟等），其产物均独立保存在 `runs/` 各测试目录下。控制台为了保证正式长辈（王大爷）档案的纯净，**绝不自动把历史测试脏数据混入真实长辈档案**。
* **基于“数据源（Source）”的接入设计**：
  控制台本身不直接抓取摄像头，而是监听各个算法模块写入的 `.jsonl` 文件。在【系统维护】中为指定长辈**绑定对应的数据源**后，后台才会持续自动读取解析。

### 2. 如何接入模块记录（将测试/实录数据绑定给长辈）
进入工作台左侧导航 **【系统维护】**：
1. **核对已绑定数据源**：
   左侧列表显示当前长辈已绑定的模块文件、读取偏移量与读取状态（正常显示绿色“已绑定”）。
2. **绑定新记录**（右侧表单）：
   * **老人档案**：选择要归属的长辈（如王大爷）；
   * **模块**：选择要接入的模块（情绪识别 / 异常监测 / 交流会话日志）；
   * **已发现的记录文件**：可直接从下拉框选择系统自动扫描到的候选日志；
   * **JSONL 文件路径**：亦可手动填入服务器上可读的 `.jsonl` 绝对路径；
   * **采集类型**：根据需要选择“历史记录 / 视频回放”或“当前实时采集”；
   * 点击 **【绑定并读取记录】**，后台守护线程会在 2 秒内自动完成历史追溯与增量监听。

## 五、 边缘至云端自动同步机制 (Auto-Sync)

系统采用**“高可靠、非阻塞的应用层增量异步推送架构”**（`care_console/sync.py`），实现现场机器人互动后 1~2 秒内自动同步至云端公网控制台：

```text
[ G1 现场互动 ] 
       │ 100% 本地边缘闭环运行，离线可用，不依赖外网
       ▼
[ 本地日志 / SQLite (console.db) ] 
       │ 
       ▼
[ 本地后台守护协程 (cloud_sync) ]
       │ 每 2 秒增量检查未同步游标
       │ 异步网络推送 (附带专用 X-Care-Sync-Token 令牌)
       │ 若遇弱网或断网：仅记录 Warning，游标保持不动，网络恢复自动续传 (绝不阻塞机器人)
       ▼
[ 云端专属接口 (POST /api/sync/push) ]
       │ 机器令牌鉴权 (无需前端登录 Cookie)
       │ 基于唯一主键 (session_key, external_id, dedupe_key) 天然幂等入库，重复推送不产生脏数据
       ▼
[ 云端管理工作台 (https://82.157.186.52:8443/) ]
       │
       ▼
[ 远程评委 / 手机移动端 ] (1~2 秒内自动刷出最新记录)
```

### 1. 同步环境配置与凭证
本地工作台启动时，会自动从 `~/.config/elder_companion/cloud.env`（或环境变量）读取配置：
- `CARE_CONSOLE_SYNC_TARGET`：云端目标地址，默认 `https://82.157.186.52:8443`。
- `CARE_CONSOLE_SYNC_TOKEN`：专属同步令牌 `250cf83a06b3dc74470a1e8537e88b06`。

### 2. 核心技术特性
1. **零阻断与离线优先**：G1 的情绪感知、对话与灵巧手动作完全在本地完成。如果现场 Wi-Fi 信号弱或完全断开，机器人正常陪伴老人，不会因网络卡顿产生丝毫停顿。
2. **断网续传与断点游标**：本地维护最后成功同步的自增 ID 游标；网络恢复后，守护协程自动把断网期间产生的所有事件、对话与照护需求批量补发至云端。
3. **老人编号多端动态映射**：云端与本地数据库的长辈自增 ID 可能不一致，同步层统一通过 `interaction_elderly_id = 1`（王大爷业务编号）进行动态映射，确保多端档案绝对精准。

## 六、 常见问题排查与注意事项 (FAQ)

### Q1: 打开 `#emotion` 或 `#anomaly` 为什么显示“暂无记录”？
* **检查 1（数据源是否绑定）**：点击左侧【系统维护】，查看“已绑定数据源”中是否有对应模块的路径。若无，请在右侧表单选择长辈并绑定对应的 `.jsonl` 文件。
* **检查 2（是否手动刷新了页面）**：情绪与异常页面为了保障阅读体验关闭了自动轮询，数据写入后需**手动按 F5** 或点击右上角 **↻ 刷新**。
* **检查 3（本地控制台进程是否存在）**：终端执行 `ss -tln | grep 8766`，确认本地 Python 服务正常监听。

### Q2: 演示过程中如何切换不同的测试视频或老人？
* 每个数据源固定绑定一位长辈。如需演示不同长辈或不同场景，建议在【系统维护】中新建长辈档案，并绑定专属的场景测试日志，避免跨长辈数据交叉。

### Q3: 为什么浏览器提示“请从护理工作台执行此操作”或 403 错误？
* 控制台具备生产级 CSRF 与 Origin 安全校验。请务必直接通过控制台页面操作，不要使用未携带 `X-Care-Console` 头部的跨域工具或直接向 POST 接口提交空请求。
