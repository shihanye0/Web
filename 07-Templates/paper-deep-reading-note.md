### 0.1 证据标记

- **FACT**：正文、附录、表格、算法、代码或实际运行直接给出的事实。
- **INFERENCE**：由 FACT 推出的有限解释。
- **HYPOTHESIS**：待验证的机制假设。
- **UNRESOLVED**：当前证据无法可靠判断的问题。

### 0.2 视觉层级约定

- **粗体**：用于结论、关键术语和读者扫读时必须看到的信息；不要整句或整段连续加粗。
- *斜体*：用于语气限定、作者判断或需要轻读的补充，不代替 FACT / INFERENCE 等证据标记。
- `<mark>高亮</mark>`：用在观点、结论或转折的核心短语；建议每 2–4 个正文段落出现 1 处，单处控制在一个短分句内。避免使用双等号包裹的高亮语法，以免与 Dataview inline query 的 `=` 前缀冲突；不要整句整段高亮，也不要用颜色暗示证据强弱。
- Obsidian callout：摘要用 `abstract`，解释/操作提示用 `info` 或 `tip`，证据边界用 `warning`，重要结果用 `important`；标题要说明内容，不按颜色给事实分级。
- 英文术语：面向中文阅读的正文中，首次出现重要英文术语时保留论文原词，并紧跟中文译名或一句通俗解释，例如 `pseudo-GT（伪真实轨迹参照，由成功轨迹构造）`；缩写首次出现时同时给出英文全称和中文含义。后续重复出现可只用原词或缩写。不能确定准确译法时，保留原词并标注其在本文中的具体作用，不猜译。
- 表格、公式、代码块和图片各自承担比较、推导、复现和视觉说明，不用额外符号重复装饰。
- 控制强调密度：每个自然段通常只有一种重点标记；标题、粗体、高亮、斜体不连续叠加。重点段落优先标出“结论/判断”短语，细节和证据仍留在正常正文中；表格不逐格加粗或高亮。

### 0.3 插件协同与视觉阅读工作流（可选）

插件只负责呈现、资产管理或流程自动化，**不改变 FACT / INFERENCE / HYPOTHESIS / UNRESOLVED 的证据等级**。按需要组合，避免为了“更像仪表盘”引入不稳定的动态区块。

| 插件/能力 | 对视觉阅读的真实作用 | 适合放在哪里 | 使用边界 |
|---|---|---|---|
| Obsidian 原生 Markdown + callout | 稳定提供标题、强调、折叠和证据边界 | 正文、摘要、局限、来源说明 | 不用颜色替代证据标签；不要整段加粗或高亮 |
| Excalidraw | 生成可编辑的流程图、概念图和轨迹解释图 | “论文图 vs 自制图”或方法主线 | 自制图必须标注；需要稳定导出时另存 PNG/SVG，不能把编辑态画布当论文原图 |
| Paste Image Rename | 启用后让嵌入图片拥有可读、稳定的文件名，降低断链和误读 | `08-Attachments` 与图片嵌入 | 先确认命名规则；文件名本身不代表来源或证据强弱 |
| Annotator | 在 PDF/EPUB 侧完成高亮、边注和回链，便于回到原页 | 来源 PDF、图表页、附录 | 批注是阅读痕迹，不能替代笔记中的页码、hash 和原图来源 |
| Templater + QuickAdd | 自动生成 provenance、视觉检查和 callout 骨架 | 新建笔记时 | 模板生成后仍需人工填写来源与核对状态 |
| Dataview | 聚合论文索引、状态和待核对项，形成可选面板 | 笔记末尾或独立索引页 | 动态查询为空或失效时不能遮挡正文；不在正文中重复所有字段 |
| Advanced Tables | 减少宽表格编辑错误，保持列对齐 | 指标、实验矩阵、图表索引 | 主要改善编辑，不会自动改善阅读宽度 |
| Omnisearch / Iconize / Spaced Repetition | 加快定位、导航和复习 | 侧栏、索引页、复习卡 | 不直接改变正文排版，不为此额外增加正文装饰 |
| Style Settings | 只有主题或 CSS 变量存在时才改变全局外观 | Vault 级主题设置 | 若当前 Vault 无自定义 CSS，不为单篇笔记引入全局样式依赖 |

推荐组合：**Templater 建骨架 → 原生 Markdown/callout 组织正文 → Excalidraw（可选）制作自制图 → Paste Image Rename 保持资产命名 → Annotator/Omnisearch 回到原始 PDF → Dataview 仅做可选索引**。
