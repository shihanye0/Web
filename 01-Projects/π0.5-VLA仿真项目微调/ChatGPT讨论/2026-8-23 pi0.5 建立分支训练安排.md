我支持你单独建立 **Pi0.5-v2 分支**，但核心不是“把现有配方全改掉”，而是把这次训练做成一个**能定位问题、能比较、能选 checkpoint 的正式基线**。

从你给出的信息看，我认为当前 Pi0.5 配方确实有明显缺陷，但其中只有三项值得第一轮直接改：

1. **没有 episode-level eval**

3. **50 帧 action chunk 与真实 runner 消费方式没有闭环验证**
    

反而“冻结视觉”“无增广”“batch=6”现在都不应该一起动。

# 三、Pi0.5-v2 第一版，我会这样设计

## 1. 数据仍然使用 P511

第一版**不要马上采更多完整 episode**。

因为现在最大问题不是 511 条“不够多”，而是：

> 511 条里面真正提供“闭手”“抬升”“腕部倾倒”的 supervision 到底有多少？

你现在已经有一个非常重要的信号：

> hand 相邻动作 median ≈ 0.00017 rad  
> p99 ≈ 0.05775 rad

说明绝大部分训练帧实际上接近静态/平滑跟随。

关键 transition 是少数。

所以应该先做：

```text
P511
├── approach
├── pre_grasp
├── grasp
├── lift
├── align
├── pour
└── recover
```

注意：

**这些标签第一阶段只用于统计、sampling 和 eval。**

不要喂给 Pi0.5。

# 四、重新做 episode-level split

当前 `eval_freq=0` 是我认为整个训练配置里最大的问题之一。

511 条 episode 不允许：

> frame random split

必须：

> episode split

我倾向于：

|Split|比例|大约|
|---|--:|--:|
|train|85%|434|
|val|10%|51|
|test|5%|26|

关键不是精确比例，而是：

### 每个 split 都要覆盖

- 抓取
    
- 抬升
    
- 倾倒
    
- 不同瓶位置
    
- 不同手臂初始位置
    
- 不同光照/遮挡条件
    

并且：

> `split_manifest.json` 一旦生成就永远冻结。

以后 v2、v2.1、v2.2 都用同一批 val/test。

这样你才真正知道哪个 checkpoint 更好。

---

# 五、不要只看 global action loss

这类任务最容易被 global loss 欺骗。

比如模型：

- approach 很准
    
- 等待很准
    
- 静态姿态很准
    
- 抓取完全不会
    
- 倾倒完全不会
    

global loss 仍然可能很好看。

所以至少拆成：

```text
overall action error
approach error
pre-grasp error
grasp error
lift error
pour error
```

再拆 joint group：

```text
arm error
wrist error
hand/gripper error
```

尤其关注：

### grasp

- 闭手 onset 是否正确
    
- 闭手幅度
    
- 是否维持 grasp
    
- 有没有闭手后马上张开
    

### lift

- grasp 后是否出现正确 arm movement
    
- 顺序是否正确
    

### pour

- wrist rotation onset
    
- wrist rotation amplitude
    
- 持续帧数
    
- 是否在抓住之前提前倾倒

# 六、Sampling 是 Pi0.5-v2 最值得改的地方

如果现在是：

> 从 P511 所有 frame/window 近似均匀采样

那模型实际上看到大量：

```text
不动
缓慢移动
接近
等待
```

而真正的：

```text
close hand
lift
rotate wrist
pour
```

被淹没了。

我不建议第一版搞很复杂的 loss weighting。

先做一个简单、可解释的 sampler：

### 例如起步方案

```text
60% normal uniform windows

20% grasp-centered windows

20% pour-centered windows
```

也就是：

> 仍然保留自然数据分布，但人为提高两个最关键 transition 被抽中的概率。

之后根据统计再调整。

比起直接复制关键帧，我更建议：

> **以 transition 为中心采完整 temporal window**

例如：

```text
-----pre-----| GRASP |-----post-----
```

而不是只拿“闭手那一帧”。

因为 Pi0.5 学的是 temporal action chunk。

---

# 七、50 帧 horizon 是第二个重点

30 Hz：

> 50 frames ≈ 1.67 s

对于：

> 手靠近瓶子 → 闭手 → 抬起

这种快速状态变化，1.67 秒已经非常长。

尤其如果 runner：

```text
infer 50
execute 50
infer again
```

那么基本就是开环执行 1.67 秒。

对抓取非常危险。

但这里我会稍微修正队友的一句话：

> **训练 prediction horizon 不一定数学上必须等于 runner execution horizon。**

现代 policy 完全可以：

```text
predict H frames
execute K frames
K < H
replan
```

问题是你们现在：

> `/chunk` reset + stochastic sampling + chunk 消费方式不明确

因此现阶段最好的办法反而是**先简化合同**。

---

## Pi0.5-v2 训练前先测一个 K

记录实机 runner：

> 一次 inference 之后到底连续执行多少帧才重新看图、重新推理？

记作：

```text
K_exec
```

比如实际测出来是：

```text
K_exec = 8
```

那第一版为了消除变量，可以直接做：

```text
H_train = K_exec
K_exec  = K_exec
```

先得到最简单闭环。

之后 v2.1 再研究：

```text
H_train = 16
K_exec = 8
```

这种 receding-horizon。

### 我不建议继续默认

```text
50 predict
50 execute
```

直到它被证明合理。

# 八、还有一个很容易被忽略的问题：时间同步

这个我建议你在开训之前一定查。

你们是：

> 30 Hz

而抓取 transition 很短。

如果：

```text
image[t]
state[t]
action[t]
```

实际上存在：

```text
image[t]
state[t]
action[t+2]
```

甚至 2～3 帧延迟，

普通移动可能还看不明显。

但在：

> 闭手瞬间 / 抬升瞬间 / 倾倒瞬间

会非常致命。

所以 P511 在重新训练之前最好测：

```text
camera timestamp
state timestamp
action timestamp
```

以及 transition cross-correlation。

哪怕只错：

> 2 frame ≈ 67 ms

都值得关注。

这个优先级甚至高于“要不要解冻视觉”。

# 九、第一版不要解冻视觉

你看到：

> frozen vision encoder

很容易直觉认为这是错误配置。

但我目前反而建议：

### Pi0.5-v2 baseline 继续 frozen vision。

原因很简单：

你只有 511 episodes。

如果现在同时：

- stage-balanced sampling
    
- horizon 改变
    
- vision unfreeze
    
- augmentation
    
- LR 改变
    

最后模型好了，你不知道为什么。

模型坏了，也不知道为什么。

而且视觉 encoder 解冻在小数据集上可能直接增加过拟合风险。

# 十、增广第一版也不要上

特别不要上：

- aggressive crop
    
- random resize
    
- random geometry
    
- camera translation
    

因为这不是 ImageNet 分类。

机器人控制里面：

> pixel location 本身具有空间意义。

第一轮如果交叉实验确认：

> train image + live state 好  
> live image + train state 差

证明视觉域偏移以后，

Pi0.5-v2.1 再上轻量 photometric augmentation：

```text
brightness
contrast
color jitter
small exposure variation
```

优先不要改几何关系。

# 十一、训练步数也不要再定死“155k / 200k”

当前：

```text
120k
155k
```

实际上没有 eval。

所以这些数字意义不大。

新的逻辑应该是：

```text
5k checkpoint
10k
15k
20k
...
```

定期跑固定 validation funnel。

最后：

> **val grasp/pour 最好的 checkpoint 才叫 best checkpoint。**

而不是：

> 最后一个 checkpoint = 最好。

甚至完全可能：

```text
65k > 90k > 120k > 155k
```

尤其小数据 fine-tuning 很正常。

# 十二、我会把 Pi0.5-v2 实验拆成这样

|实验|改什么|不改什么|目的|
|---|---|---|---|
|A0|不训练，评测120k/155k|全部|建 baseline|
|A1 / v2|eval + stage sampler + 合理 horizon|frozen vision、无 aug、原 prompt|判断 temporal/action 学习能力|
|A2|horizon ablation|sampler/data 不变|找最佳闭环长度|
|A3|photometric aug|action合同不变|验证视觉泛化|
|A4|partial vision unfreeze|其他不变|视觉确实是瓶颈才做|
|A5|新增 transition 数据|网络不变|判断数据瓶颈|
|A6|state/memory|基础 skill 已稳定|做长任务编排|

这里最关键的是：

> **不要直接从 A0 跳到 A6。**

# 十三、关于你这个“明显分段”的倒药任务

我仍然建议：

## VLA 内部学连续技能

例如：

```text
抓瓶 → 抬瓶 → 对准 → 倾倒
```

这段最好是 Pi0.5 自己连续完成。

## 外部状态机负责

```text
进入任务
↓
瓶子是否存在
↓
是否达到抓取工作空间
↓
调用 pour skill
↓
成功/失败判断
↓
重试 / 恢复
```

而不是：

```text
状态1 -> 手工走到A点
状态2 -> 强制闭手
状态3 -> 手工抬腕
状态4 -> VLA
```

后者最后会变成传统 scripted policy，不是在验证 VLA。

# 十四、所以现在先不要加 memory / 状态记给 Pi0.5

这一点和我们之前讨论 Psi0 是同一个原则。

现在你要回答的是：

> **Pi0.5 本体到底能不能学会这一段 manipulation primitive？**

也就是：

> 看到当前 image + state + task  
> 能不能正确产生  
> 抓取 → 抬升 → 倾倒

如果先加：

```text
state = GRASP
memory = 瓶子已经抓住
```

成功以后并不能证明 Pi0.5 本身解决了问题。

所以：

> **阶段标签先用于监督训练质量，而不是作为模型输入。**

这是我非常建议你坚持的一点。

### Gate 1：数据合同



> **Pi0.5-v2 可以训练，但它就不再是最高优先级。**
